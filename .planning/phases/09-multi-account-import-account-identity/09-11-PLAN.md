<objective>
Close VERIFICATION Truth 21 and the two open UI-review findings it carries: a two-folder archive whose second folder stores nothing must not render the single-account header, and the spec must say which folders each count describes.

Purpose: 09-10 chose option-a (count the accounts that hold data) and implemented it as specified. The shell then used that filtered list to decide something it was never meant to decide. `accountCountOf` answers 'how many accounts hold data?', and `isMultiAccount`, the header's variant switch, asked the same function 'does this archive hold more than one account?'. For a two-folder archive with one data-less folder the answers differ, so the header took the `loaded` branch and showed `result.identity`, which is the first folder's, as the export's nickname, REGION and CREATED_AT. UI-SPEC Surface 3 forbids exactly that. The Account list row (headline = the first account's location code) and the Overview Account card (summary = the first account's creation date) read the same legacy field behind the same filtered count, so they carry the same defect on the same surface and are fixed by the same predicate.

The fix is two numbers with two names. A new `ClassifyResult.rootCount` carries the account folders the archive held; `accounts.length` keeps meaning the accounts that hold data. One predicate, `hasMultipleRoots`, answers every variant decision; `accountCountOf` keeps answering every title, row-count and caption decision. 09-10's option-a semantics for the title, the rows and the captions are not changed.

Output: the root count on the result from all three producers, the predicate and its callers, the singular title copy the new state makes reachable, a worker-boundary regression, a browser step folded into the existing lifecycle test, and a dated UI-SPEC amendment.
</objective>
