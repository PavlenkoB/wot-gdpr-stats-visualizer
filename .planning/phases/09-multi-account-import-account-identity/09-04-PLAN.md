## Planner choices (so the executor does not "correct" them)

1. **Open Question 5 (nickname exactly once).** v1.0 D-21 says the nickname appears once in the document. With several accounts the rule is restated as once per account row (UI-SPEC Accessibility). This is a restatement for N >= 2; the one-account DOM and its assertions are unchanged.
2. **Open Question 7 (game names).** One token table for the long names, used only by the identity list; WOWP is added although D-14 lists five names (UI-SPEC recorded choice), so a Warplanes session shows a name and not a raw token. Remove it only if the user asks.
3. **The shell never re-sorts.** The worker stores D-16 order and every producer uses `sortAccounts`; the header renders the order it is given. Keeping one comparator in one place avoids two sorts that could disagree.
4. **Earliest created date.** `earliestCreated` is defined here (plan 09-05 consumes it) with a pure wall-clock parse: it accepts a date part written `YYYY-MM-DD` or `DD.MM.YYYY` (with any time after a space or T), range-checks the month and day, compares the normalised numbers and returns the winning date text as `formatCreatedDate` would show it. It never constructs a `Date`, so no timezone can shift a day (the rule `formatCreatedDate` documents). A value in another shape does not parse and is skipped.
5. **One browser test, extended later, because the e2e budget is nearly spent.** `playwright test --list` reports 256 tests today against the guard's ceiling of 258 (D-23: the figure of 252 in the research and in the Phase 8 comment of `ci-budget.test.ts` is stale; plan 09-06 reconciles it), so the whole phase adds exactly two listed tests. The test created here is the first: it covers the header, the leak scan of the landing view and the Account pane, and the reload, written as `test.step` blocks. Plan 09-05 appends steps to the SAME test (every pane, the captions, the one-account replace), because the pane-by-pane scan needs its keyed-list fixes; plan 09-06 adds the second test. The existing identity-privacy tests are not edited.
