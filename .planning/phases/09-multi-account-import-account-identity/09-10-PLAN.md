<objective>
Settle the UI audit's first-ranked finding: the header can say "3 accounts" while one of the three rows reads "No activity recorded", because the count describes the archive's roots rather than the accounts the dataset actually holds data for.

Purpose: ACCOUNT-05 and D-13 promise a list of accounts with their games and their first-to-last activity. A root the import stored nothing from is in neither of those, so counting it makes the title, the list and every pane's caption three different statements about one dataset. This is the same defect class the phase spent 09-04 preventing — a row that presents one account as the whole, or a phrase that describes the archive rather than the data — and the phase's own verification could not score it because the count itself is correct arithmetic over the wrong set.

The finding is a product decision, not a code fix: hiding a folder the user can plainly see in their zip is as arguable as labelling it. So this plan opens with a human decision and then implements the chosen answer.

Output: the decision and its rationale, the persisted flag that makes the answer reproducible on a reload, one projection shared by the import and every replay, a fixture whose data-less root is real rather than hypothetical, and the cases that pin the chosen semantics.
</objective>

Write it in the same `meta.put` that already stores the record, in the same list the import already builds, computed from that root's own running state. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored record to published list | What the import writes is re-read on every reload; a field absent from an older record must not change what a returning user sees |
| account list to rendered count | The number in the title and every pane caption is derived from the published list, so one projection decides all of them |
| account record gate to account list | The rule that keeps one account's address out of a multi-account dataset must not follow the published list |
