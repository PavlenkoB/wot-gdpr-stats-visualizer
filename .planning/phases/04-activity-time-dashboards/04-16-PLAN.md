## Decision recorded: what counts as "the cached data was cleared"

The worker answers `importedAt: null, view: null` only when the stored dataset is gone (no meta record, or the rows vanished between the two reads). A tab that holds a dataset in memory and receives that answer has been told the store was emptied under it. Two neighbouring cases are NOT this gap and are deliberately left as they are: an answer stamped with a different, non-null dataset (another tab replaced the export), and an answer with a stamp and no view (the worker has no stored aggregate). Both stay silent drops with the existing reconcile, because the sentence below would be false for them. The replaced-in-another-tab case is worth a separate notice with its own copy if it is ever reported; it is recorded here so it is a choice and not an oversight.
