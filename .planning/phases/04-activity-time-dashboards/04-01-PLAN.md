<objective>
Prove the backend half of the Phase 4 architecture with one thin, production-quality path: a `Sessions.csv` row travels through the import worker (strict timestamp parse, merge-aware sweep), is persisted on the dataset meta record, is read back by a `playtime-query` round trip and crosses a rune-free `PlaytimeClient`, which `IngestClient` feeds without touching its own state machine.

Purpose: every later plan (full aggregation, split, charts) builds on the stored shape, the message contract and the delegation seam proven here. Getting the seams wrong (a Dexie schema bump, aggregates riding ClassifyResult, a shared jobId) is expensive; getting them right once, end to end through the real worker, is cheap. This plan is the worker-and-contract half of the phase tracer; plan 04-02 is the client-and-UI half (status flip, the Playtime block, the migrated Phase 3 assertions) and completes the path to a visible tile. The two are separate plans so each fits one executor context.

Output: the shared constants, the final `PlaytimeSlice` / `PlaytimeAggregates` / `PlaytimeView` contract, an All-slice aggregator, the persistence and query handler, the `PlaytimeClient` and its IngestClient delegation.

Decisions implemented here: D-01 (wall-clock basis, costly), D-02 (usable-session and exclusion rules, merge-aware seconds and start-day attribution), D-06 (Sessions count for the slice). D-03's aggregation shape (per-slice buckets, one All slice plus one slice per value) is fixed here in the type contract and filled in by plan 04-06.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| zip CSV cell to worker aggregator | Every Sessions.csv cell (timestamps, server and platform names, IP) is untrusted attacker-controlled text |
| worker to main thread | Only the aggregate view (numbers and, later, split labels) crosses; raw rows and the IP column never do |
| meta record to a later query | The stored aggregate is read back verbatim; a version marker decides whether it is trusted |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Information disclosure | Sessions IP column reaching meta.playtime, a message or the DOM | high | mitigate | resolveSessionColumns returns only four key names and values are read by direct property access on those keys; the persistence test asserts the fixture IP is absent from JSON.stringify(meta.playtime); the type contract has no IP field; plan 04-03 adds the throwing-getter test and plan 04-11 the DOM assertions |
| T-04-02 | Tampering | Hostile timestamp string (regex backtracking, impossible date, offset) | medium | mitigate | One anchored regex with no nested quantifiers, explicit calendar validation via daysInMonth, offsets rejected and counted as excluded rather than silently ignored |

| T-04-04 | Information disclosure | Console output carrying row contents | low | mitigate | The catch logs a fixed message plus the Error object only; no row, cell or value is interpolated into any log line |
