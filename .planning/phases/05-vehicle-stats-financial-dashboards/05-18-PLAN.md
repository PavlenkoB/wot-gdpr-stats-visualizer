<objective>
Close UAT gap G-05-3: the premium-per-month chart must bucket each grant by its real date, which in a real export is `CURR_PREMIUM`, not `CREATED`.

Purpose: `buildPremium` reads `CREATED` for the month. In the user's real export `CREATED` equals `UPDATED` on all 128 rows and is a bulk-migration stamp (18 rows on one day, 16 on another), while `CURR_PREMIUM` holds the operation datetime the user's real-export comparison identified as the real date. The chart therefore showed "35 of 94 months" with 2013-12 at 137.3 days where the real dates give 32 months with 2014-01 at 58.0 days (total 577.3 days either way, because parsing was never wrong). The 05-01 fixture encoded the opposite column semantics (an invented currency code in `CURR_PREMIUM`, the real date in `CREATED`), so every test agreed with the bug.

This amends locked decision D-19, which literally says "bucketed by `CREATED`". D-19's intent is a month of premium days GRANTED, so the amendment keeps the intent and corrects the column, on the strength of the UAT real-export comparison; the original text stays in place with a dated amendment beneath it. D-20 (unreadable values are counted, never guessed) and D-03 (fixtures with the real shape, no real data) govern how the fix behaves and how it is tested.

Output: a corrected `buildPremium`, a real-shaped fixture and independent oracle, updated unit, worker and browser specs, and amended contract documents.
</objective>
