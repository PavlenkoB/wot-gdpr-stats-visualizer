## Planner assumptions and flags

- **Plausible-date window.** Planner decision, flagged in plan 05-01 and for the user: a date is readable only when `parseSessionTimestamp` accepts it and its year is within 1970 to 2100. Plan 05-08 puts the matching clause into the approved excluded-notice copy.
- **Negative currency amounts.** A negative AMOUNT on a virtual-currency row is treated as non-numeric (excluded and counted), because direction comes from TYPE and a signed amount contradicts it. The real sample has only non-negative integers, so this is a defensive rule.
- **Unrecognised string order.** Listed strings are ordered by occurrence count descending then code-unit order; at most 1,000 distinct strings are tracked, so `unrecognisedMore` is a lower bound beyond that.
- **`paid` is the included count.** `SpendCard.paid` counts PAID orders that went into `units`; PAID orders with a non-numeric amount are in `excluded` and in neither `paid` nor the breakdowns. The breakdown order counts therefore sum to `paid`.
- **Spend has no not-in-export state.** UI-SPEC lists only loading, ready, no-usable and error for the spend block, so an absent or empty Orders file is `no-usable`.
- **Display rounding of breakdown rows.** Each breakdown figure is rounded once for display from its own exact sum, so displayed rows can differ from the displayed headline by a cent in general; the exact micro-unit sums always add up and the tests assert that, not the displayed text.
