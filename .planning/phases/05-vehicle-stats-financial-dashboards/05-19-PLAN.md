<objective>
Close UAT gap G-05-7 (cosmetic): the identity header shows `Account_Info.REGION` under a label that makes it read as a game realm, but in the user's real export the value is a numeric regional code ("30") that sits beside a city, not a server.

Decision, taken here as the lowest-risk option: RELABEL, do not hide and do not derive.
- Hide is rejected because IDENTITY-01 and the Phase 3 success criteria promise the header shows the region, and eight e2e assertions depend on the `identity-region` element.
- Derive is rejected because the export carries no realm field; the only candidates are other Account_Info columns, and reading them would widen the three-field identity that Phase 3 D-18 to D-20 keep deliberately narrow.
- Relabel changes only the label constant, keeps the raw value per Phase 3 D-13 ("never mapped to a friendly name"), and is reversible with a one-line edit. The new text is "Location code (per export)": "code" says it is an opaque value, "Location" avoids the realm vocabulary the old label invited, and "(per export)" keeps attributing it to the file. If the user prefers different wording, only the constant and its pinned test string change.

Purpose: stop the header making a wrong implied claim about the user's account.
Output: the relabelled constant, its pinned test, a corrected component comment, and the amended Phase 3 copy contract and decision record.
</objective>
