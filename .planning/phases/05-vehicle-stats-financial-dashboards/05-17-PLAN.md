<objective>
Close UAT gap G-05-4: the virtual-currency builder must count an `income` operation as up, as locked decision D-18 says, so an income-only currency (the user's real UAH, five `income` rows totalling 821) no longer reads "Deposited 0 / Withdrawn 0 over 5 operations".

Purpose: `buildCurrency` accepts TYPE income as a usable operation but leaves it out of both sums, so the code contradicts D-18 (`deposit` and `income` count as up, `withdrawal` as down) and the Other currencies line, the chart bars and the month cell labels all understate real inflow. The plan-04 executor kept the code, the hand answer key and the oracle in agreement with each other but against the written decision, so no test could catch it. This plan fixes the decision-bearing code, re-derives the answer keys by hand, adds a real-shaped income-only fixture, and adds a browser proof and a scale guard.

Output: a corrected `buildCurrency`, an oracle and hand key that agree with D-18, an income-only fixture, updated unit and browser expectations, and stale comments removed.
</objective>
