## Planner assumptions and flags

- **Withdrawal strings are recognised, so the disclosure is renamed (planner decision, flagged).** The approved heading was Unrecognised premium values, which would be false for a withdrawal row. The amended heading is Premium values not charted. The user asked for the strings to be listed "like unparseable rows"; the heading is the minimal honest wording change.
- **Plausible-date window (planner decision, flagged).** The amended explanations say "a date that cannot be read", and the spec states that a date outside 1970 to 2100 counts as unreadable. This bounds the month axis (plan 05-04, T-05-08) and is the only way the user's one-clause extension stays true.
- **Negative currency amount.** Written into the spec as part of "a non-numeric amount".
- **Tooltip sizes line.** Premium extras are one line of sizes joined by commas with a trailing "+k more sizes" when sizes were dropped, then the basis line; the UI-SPEC text is ambiguous between one line and several, and one line keeps the tooltip inside its 240px width.
- **Resetting modules.** A test that calls vi.resetModules and imports ui-copy again gets a fresh default locale and must call the seam itself; the doc comment says so.
- **Task order is deliberate.** The UI-SPEC amendment (Task 2) precedes the copy implementation (Task 3) so the strings are copied into tests from the amended spec, not from the superseded one.
- **Task 1 touches many e2e files** only to add one import line each; no assertion changes except the one local `toLocaleString` call in persistent-dataset.spec.ts.
