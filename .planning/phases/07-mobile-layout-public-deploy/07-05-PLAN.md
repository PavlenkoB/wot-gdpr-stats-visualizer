<objective>
Make the finished dashboard fit and work at phone width: one 480px block in `src/app.css`, a sweep spec that proves no section or state scrolls the page sideways at 375px, and bounding-box proof that every button, summary and link is a 44px target (PLATFORM-01, SC1; D-01, D-02, D-03, D-04, D-07, D-08, D-16).

Purpose: Phases 4 to 6 already contain most of the wide content inside its own scroller; what phase 7 adds is the smaller page padding, a touch-sized hit area, and an automated sweep so none of it can regress. The one risk is the global 44px floor: nav links are about 39px tall today, so lifting them to 44px would make the nav about 6px taller, and `--nav-offset` is a single number that the calendar's sticky head, every anchor's scroll margin, the scroll-spy band and the tooltip placement all read; two existing specs also pin the nav geometry (the calendar head parks at 56px at 375px; the nav's height must match between phone and desktop within 4px). The plan keeps the nav's height by trimming its own padding at phone width, and measures instead of assuming.

Tracer: Task 1 is the padding block plus the first sweep test: a real browser at 375px and at 481px proving the breakpoint and the no-overflow baseline. Task 2 adds the 44px floor, re-measures the nav, and proves the targets and the offset contract on the touch project. Task 3 completes the sweep across every section and state, and does the CI budget bookkeeping.

- Mechanics: a global `min-height` does not collide with a component's `height: 40px` (different properties; the larger wins), which is why a global rule can work for buttons and summaries. The project has no global border-box reset, so the floor must set `box-sizing: border-box` with it: with the default content box a 44px minimum would stack each target's padding and border on top (a city opt-in button would measure about 60px). A link is inline and ignores `min-height` until its display changes; the nav links already set `display: block` in their own scoped rule, which outranks the global one.
- New specs under `tests/e2e` that import anything from `ui-copy` must also import `../_support/pin-locale` first: a unit guard (`tests/unit/shell/ui-copy.test.ts`) fails any e2e spec that imports the copy module without pinning the locale.
