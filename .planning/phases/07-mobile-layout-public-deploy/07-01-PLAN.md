<objective>
Make the app servable under the GitHub Pages project subpath and prove, on the exact built artifact, the guarantees the product is for: the worker and favicon resolve under the base, the CSP and zero-network checks hold, and the opt-in city file is served with the byte count and sha256 its manifest records (PLATFORM-03; decisions D-11, D-12, D-13, D-14, D-15).

Purpose: the deploy workflow (plan 07-02) is only as trustworthy as the gate it runs before uploading. This plan builds that gate as a Playwright harness that serves a prebuilt `dist` (no rebuild, so it tests the bytes that ship) and a spec that is deliberately shared with the post-deploy live smoke: the same assertions, two base URLs.

Order of work inside this plan: Task 1 is the D-12 precondition checkpoint (locked as the first task of the phase; it is a record, not a gate, and its answer may be `deferred`). Task 2 is the tracer: one build under the real base, served under the real base, one Playwright path through it. Task 3 expands the gate to the CSP, zero-network, city-file and artifact-content checks.

Execution constraints (decisions already made, none reopened):
- The ONLY production-code change is the `base` line in `vite.config.ts` (D-11). `index.html` is NOT edited: verified at planning time by `vite build --base=/wot-gdpr-stats-visualizer/`, which rewrites the favicon, script and stylesheet URLs and the worker chunk URL itself. A relative `./` base is rejected because `cityAssetUrl` concatenates origin + `BASE_URL`.
- `CSP_POLICY` stays exactly as it is (D-15, `connect-src 'self'`). No origin is baked in.
- No package is installed, including dev dependencies (T-07-SC). Everything below uses what is already in `package.json`.
- The new configs and specs live under `tests/deploy/`, not `tests/e2e/`: the default config lists only `tests/e2e`, so these are never run by `ci.yml` against `localhost:4173` at `/`, and `tests/unit/guards/ci-budget.test.ts` never counts them.
- The geo fixture switch is selected in exactly one place in this repository (the main `playwright.config.ts` webServer env, pinned by `tests/unit/guards/geo-seam.test.ts`). The deploy build has no fixture: nothing in `tests/deploy/` may set or even name that variable. Comments in the new files must describe it as "the fixture switch".
- Commits: one per task. NO `Co-Authored-By` trailer on any commit (project rule). Run `pnpm exec prettier --write` on every new or changed file before committing: `pnpm run lint` runs `prettier --check .`.
</objective>
