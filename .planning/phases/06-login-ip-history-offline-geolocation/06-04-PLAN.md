Tracer exception to the five-file guideline: a tracer crosses every layer this plan owns by definition, so this task touches 9 files, each kept to the thinnest body that is still production quality and each extended by the expansion tasks that follow.
Build the container and one real path through it. Per D-12 the lookup data is generated at build time and consumed in the worker; per D-17 fixtures use documentation ranges only.

1. `src/lib/geo/range-table.ts` (pure; the only import is `./ip.ts`; no DOM, no Node API, so the worker, the scripts and the tests can all import it). Define the exported constants `KIND_COUNTRY = 1` and `KIND_CITY = 2`, the interface `RangeTable` (kind, month as `YYYY-MM`, fixture boolean, places as a string array, unknownId, `v4Starts` Uint32Array, `v4Ids` Uint32Array, `v6Hi` BigUint64Array, `v6Lo` BigUint64Array, `v6Ids` Uint32Array), `encodeRangeTable(input)` and `decodeRangeTable(bytes)`. The encoder takes a list of ranges (start and end as `ParsedIp`, place string), a kind, a month and a fixture flag; it sorts per family, fills every gap and the leading hole with the explicit unknown place (the string `ZZ` for a country table, the empty place for a city table), and merges adjacent ranges of the same place, so a mirror source without ZZ rows resolves identically. Layout, kept deliberately simple and exact: a fixed header (magic, version, kind, flags with bit 0 = fixture, month, place count, v4 count, v6 count), the place table (UTF-8, newline separated, byte length first), the IPv4 section (start deltas as varints, then place ids as varints), and the IPv6 section (high-64 deltas as varints, the low-64 plane, then place ids). IPv6 starts are stored exactly: 419 of 348,712 real starts have a non-zero low half and a truncation to the high 64 bits collided 298 country ranges (RESEARCH measurements), so never truncate. The low-64 plane is almost all zero and may be stored sparsely. `decodeRangeTable` validates BEFORE trusting any length: magic, version, kind, flags, that the counts agree with the section byte lengths, that every start is strictly greater than the previous one, that every place id is below the place count, and a hard cap on counts and total bytes; any failure throws one fixed `Error` text and never includes bytes or offsets in it.
2. Lookup, all pure, all taking the table as an argument: `lookupV4(table, addr: number): number` and `lookupV6(table, hi: bigint, lo: bigint): number` (predecessor search: the id of the last range whose start is at most the address; the table always starts at address zero after normalisation, so an id is always found), and `lookupIp(table, ip: ParsedIp): number`, which reads the bytes, resolves an IPv4-mapped IPv6 address through the IPv4 section using `mappedIpv4`, and otherwise searches the family section.
3. `scripts/geo/lib/csv-ranges.ts`: a quoted-field-aware line splitter (the city files quote fields; plan 06-09 reuses it) and `parseCountryLine(line)` for `start,end,CC` that returns a range using `parseIp` from `src/lib/geo/ip.ts` (imported with its explicit `.ts` extension) or null for a header, blank or malformed line.
4. `scripts/geo/build-country-table.ts`: a Node CLI run as `node scripts/geo/build-country-table.ts` (native type stripping, no flag; keep it erasable: no enum, namespace or parameter property; CI runs Node 24 and 06-RESEARCH assumption A2 is that this works there without a flag, which the unit tests that spawn the scripts will confirm in CI, so record the Node version in the SUMMARY). Flags: `--csv <path>` (plain or `.gz`, detected by the gzip magic bytes, not the extension), `--out <path>` (default `src/lib/geo/assets/country-table.bin`), `--fixture` (sets the flag bit), `--month YYYY-MM` (the label recorded in the header; required with `--csv`). Stream the input line by line (createReadStream, createGunzip when gzipped, readline) and never hold the file as one string. Print exactly one summary line: kind, month, range counts per family, byte size, sha256 of the written file. `--download` is added in Task 3 after the source decision.

6. `tests/fixtures/geo/country-fixture.csv`: hand-authored, `start,end,CC` lines, documentation ranges only (RFC 5737 and RFC 3849). Map each /27 block of 192.0.2.0/24, 198.51.100.0/24 and 203.0.113.0/24 to a distinct country, including Singapore (a tiny-country case for the map) and Gibraltar (a code with no polygon), make the block 203.0.113.224/27 explicitly `ZZ` (it contains 203.0.113.230, the hand fixture's third address from plan 06-01, so plan 06-06 can assert a documentation address that resolves to an explicit unknown), keep 192.0.2.10 and 198.51.100.20 inside two blocks mapped to two countries, split one /27 into two adjacent /28 ranges of the same country (to exercise merging), and map each of forty /48 blocks of 2001:db8::/32 to a country.
