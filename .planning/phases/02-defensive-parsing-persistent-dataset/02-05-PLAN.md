## Facts verified against the installed PapaParse 5.7.0 while planning (re-verify cheaply in the RED step; do not assume)

- A quoted field that never closes yields one `Quotes` error (code MissingQuotes) whose swallowed cell holds every remaining source line. A later lone quote can close it early instead, yielding InvalidQuotes with two physical lines merged into one cell.
- `error.index` for Quotes errors is the character offset just AFTER the opening quote, relative to the BOM-stripped string that was passed in (so the character at index - 1 is the quote).
- A Quotes error inside the header record carries `row: 0`.
- `result.meta.linebreak` is the line terminator PapaParse actually used (CRLF, LF or CR) and `result.meta.fields` is the header key list.
- With `skipEmptyLines` false, a leading blank line becomes the HEADER (fields = [""]) and a trailing terminator yields a final one-key record whose value is "". The wrapper must therefore strip leading blank lines itself and filter blank records itself.
- A quoted header cell that contains the delimiter (for example `"LOGIN;BIRTH_DATE"`) is unquoted by PapaParse into the single key `LOGIN;BIRTH_DATE`. The anchored `DROPPED_COLUMN` regex does not match it, so neither pinning `;` nor any delimiter heuristic is a sufficient guarantee on its own. The key check is.
- The real export shape (see `renderCsv` in `tests/fixtures/export-fixtures.ts`) is: a leading CRLF, the header, CRLF, then CRLF + row + CRLF per record, i.e. a blank line between every record. Several payment-era files are bare-CR terminated and quote every cell.
