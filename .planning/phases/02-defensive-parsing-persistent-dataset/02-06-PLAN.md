## Facts verified while planning (re-verify cheaply in each RED step, do not assume)

- PapaParse 5.7.0 uses ONE line break per file. When `newline` is unset it calls `guessLineEndings`, which looks at only the first 1 MiB, strips quoted spans, then returns LF when no CR exists or LF appears first, else CRLF when at least half of the CR-split segments start with LF, else CR (`node_modules/papaparse/papaparse.js` lines 1019-1023 and 1099-1125). A terminator of another kind inside that file is cell data. A `newline` of `'\n'`, `'\r'` or `'\r\n'` is honoured as given; `undefined` means "guess".
- The verifier's W-2 probes, against the current parser: `A;B CRLF 1;2 LF 3;4 CRLF 5;6 CRLF` gives `{A:"1", B:"2\n3", __parsed_extra:["4"]}` plus one clean row, skippedCount 0. The same text with a bare CR between `1;2` and `3;4` gives `B:"2\r3"` and `__parsed_extra`. With a stray quote on the third record (`3;"abc`) the valid `1;2` is lost and skippedCount is 1. An all-quoted file with CRLF, CR and LF mixed returns rows [] and skippedCount 1: the whole file is lost and counted once.
- On a body whose terminators were all rewritten to LF and parsed with `newline: '\n'`, `Quotes` errors, `error.index` (offset just after the opening quote) and `meta.linebreak` behave exactly as the 02-05 facts record, with `meta.linebreak` equal to LF.
- `toUpperCase` already folds U+0131 (dotless i) to I and U+017F (long s) to S, and NFKC folds fullwidth forms, the Kelvin sign and compatibility Roman numerals to ASCII. A second NFKC pass after upper-casing changes nothing that matters (brute-forced over every code point while planning). So the order NFKC, trim, upper-case, fold is sufficient.
- UTS #39 confusables.txt v18.0.0 (2026-08-06) has no Cyrillic or Greek capital twin for L or R, and for G only U+050C. Every deny-listed name contains an L (LOGIN) or an R (BIRTH_DATE, BIRTH_DATE_SRC), so no purely Cyrillic or Greek word can fold into one of them. A fold-triggered strip therefore needs a key that already carries a real ASCII L or R, which is why native-script column names are not dropped.
- ESLint `no-control-regex` rejects a `\u0000` range inside a regular expression. A non-ASCII test must use the Unicode property escape for non-ASCII (negated ASCII property) instead.
- 02-05's predicate splits the trim-and-upper-case of the RAW key on the wide class outside ASCII A-Z, 0-9 and underscore, so EVERY non-ASCII character, invisible or not, separates tokens. A first draft of this plan removed invisible characters and kept letters inside tokens before splitting; against the 02-05 shapes below that draft failed five of eight (ID + zero-width space + LOGIN, LOGIN + zero-width space + BIRTH_DATE, LOGIN + U+00E9 + BIRTH_DATE, LOGIN + fullwidth A, LOGIN + U+FF3F + 1), the last two because NFKC turns the separator into a word character. The design below therefore keeps the 02-05 split verbatim on the raw key and only ADDS rules.
- UTS #39 lists U+0399 (Greek capital iota), U+0406 (Cyrillic Ukrainian I) and U+04C0 / U+04CF (palochka) with the lower-case l as prototype: they are ambiguous between the capital I and a lower-case l. Folding one to I is right when it stands for the I of LOGIN and wrong when it stands for the L of a lower-case `login`. Folding replaces an unknown by a certain letter, which would erase the unknown signal, so the resemblance rule reads the PRE-fold form.
