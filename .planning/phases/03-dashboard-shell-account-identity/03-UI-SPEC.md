## Spacing Scale

Declared values (multiples of 4) — the Phase 2 scale, unchanged:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between adjacent `dt`/`dd` rows in the identity header; gap between count text and skip tag |
| sm | 8px | Gap inside a section card between heading, status line and summary; nav vertical padding; nav link vertical padding; button padding-y |
| md | 16px | Card padding (identity header, sections, banners); button padding-x; column gap in the identity `dl` |
| lg | 24px | Vertical gap between the page's top-level blocks (h1, import region, identity header, nav, sections wrapper) and between sections; `main` padding |
| xl | 32px | not used |
| 2xl | 48px | not used |
| 3xl | 64px | not used |

Page layout: `main` stays `max-width: 720px`, `margin: 0 auto`, `padding: 24px` (App.svelte's override; the legacy 20px horizontal padding in `app.css` is superseded). Top-level blocks live in one flex column with `gap: 24px`. All flex/grid children that hold untrusted text set `min-width: 0` and `overflow-wrap: anywhere`.

**Exceptions (pre-existing, continued — no new ones beyond those listed):**
- `12px` — notice padding-y and the gap between a notice and the next element in the import bar (same as `FailureBanner` and the Phase 2 banners). Also the padding-y of the slim import bar and the gap between the spinner and its text.
- `20px` — `.dropzone` padding in the full-size variant (unchanged). The compact variant uses `8px 12px` (both multiples of 4).
- Nav link horizontal padding is `8px` (sm); the nav container's horizontal padding is `8px`. Rationale: the five links must fit one row at the 720px column width (estimated 637px of link text plus padding, about 653px, against 672px of content width) and the container must leave room for the 3px + 2px focus ring so `overflow-x: auto` does not clip it.
- `--nav-offset: 72px` (a multiple of 4; not a scale token): the value of `scroll-margin-top` on every anchor target. Derived as nav height (about 56px: 8 + 39 + 8 + 1px border) + 16px md breathing room. It is a single custom property in `app.css` so Phase 7 can change it in one place.
- Stroke widths (1px, 2px, 3px borders and outlines) are not spacing tokens. The active-link underline is 3px, matching the focus-ring width already in the codebase.
- `1px` visually-hidden clip pattern (already used in `Dropzone.svelte`) is reused for the screen-reader-only status suffix on nav links; not a layout dimension.

## Page Anatomy & Interaction Contract

### Document order (fixed)

```
main
  h1  "WG Data Export Viewer"
  [state checking-cache → spinner block only, then STOP; nothing below renders]
  Import region        (full dropzone  OR  slim import bar)   ← contains the notice slot
  Identity header      (skeleton OR loaded)
  Sticky nav           (5 links)
  Sections wrapper     (flex column, gap 24px)
    #activity-history    Activity_history
    #player-statistics   Player_statistics
    #payment-history     Payment_history
    #user-info           User_Info
    #not-yet-supported   Not yet supported
```

Landmarks: `<main>`, `<nav aria-label="Dashboard sections">`, each block a `<section>` labelled by its own heading via `aria-labelledby` — **except** the identity header, which uses a static `aria-label="Account identity"`. It must not use `aria-labelledby` pointing at the nickname (D-21: the nickname appears in the header text only, never in an aria-label or accessible name of another element). All sections are always expanded (D-06).

Anchor ids (kebab-case, stable; Phases 4-6 build on them): `activity-history`, `player-statistics`, `payment-history`, `user-info`, `not-yet-supported`. The id sits on the `<section>` element and `scroll-margin-top: var(--nav-offset)` (72px) is set on it. This is a small deviation from D-04's wording ("headings use scroll-margin"): scrolling to the card's top edge keeps the card border visible, and the heading is the card's first child so the result is equivalent.

### App-state matrix (what renders in each client state)

The dashboard is driven by the **last known cached result**, not by the transient state name (D-27). The client must keep a separate displayed result that survives `processing`, `error`, `duplicate` and `confirm-pending(replace)`; today `IngestClient` sets `result = null` on replace-confirm and in `#fail`, so the planner must decouple them (see UI Considerations, row "error, replacement").

| Client state | Import region | Identity header | Nav / sections | Notice slot |
|--------------|---------------|-----------------|----------------|-------------|
| `checking-cache` (D-28) | not rendered | not rendered | not rendered | spinner + `Checking for a saved export...` only (this is the whole page body, `role="status"`) |
| `idle`, no cached result (first visit) | full dropzone | skeleton | nav all muted; all sections `not-loaded` | empty |
| `idle` after clear (`justCleared`) | full dropzone | skeleton | same as first visit | `Cached data cleared` |
| `processing`, no cached result (first import) | full dropzone, disabled | skeleton | skeleton stays | spinner + stage/progress text |
| `error`, no cached result | full dropzone | skeleton | skeleton | `FailureBanner` |
| `done` | slim bar | loaded | live statuses | empty |
| `duplicate` | slim bar | loaded (unchanged) | unchanged | `This export is already loaded — skipping re-import` |
| `processing` with cached result (replace) (D-27) | slim bar, drop area disabled | loaded (old data) | old data, unchanged | spinner + stage/progress text |
| `error` with cached result | slim bar | loaded (old data) | old data | `FailureBanner` |
| `confirm-pending` (replace / start-over / clear) | slim bar + `ConfirmPanel` directly below the bar's controls | loaded (old data stays visible until confirmed and finished) | old data | empty |

Notices never auto-dismiss (Phase 2 D-06); the next user action replaces them. After the worker acks a confirmed clear the client goes to `idle` with no result, which collapses to the first-visit skeleton plus the cleared notice.

### Import region

One DOM element in both modes: `<section aria-label="Import" data-testid="import-bar" data-variant="full|slim">`. Variant is `slim` iff a cached result exists, else `full`.

Internal order (top to bottom), all children separated by 12px:
1. **Notice slot** (always in the DOM, even when empty)
2. Slim mode only: meta row (imported-on text left, two buttons right, `flex-wrap`, gap 8px 16px, `align-items: center`)
3. Dropzone (full-size in `full`, compact in `slim`)
4. `ConfirmPanel` when `confirm-pending`

**Notice slot.** One `<div data-testid="notice-slot" role="status" aria-live="polite" aria-atomic="true">`. It is never conditionally rendered (a live region must exist before its content changes for announcements to work); when empty it has no height, margin or padding (children carry their own `margin-bottom: 12px`, so an empty slot adds no gap). It holds at most one notice, chosen by state per the matrix. Inside the slot the child notices must not add their own `role="status"` (drop it from the cleared notice and from the processing block to avoid nested live regions). `FailureBanner` keeps `role="alert"` (an error interrupting is intended). Every notice is text-first; colour only reinforces it. Notice chrome: `padding: 12px 16px`, `border: 1px solid`, `border-radius: 6px`, Body role, plus:

| Notice | Palette | Content |
|--------|---------|---------|
| Processing | Neutral-info | Row (`gap: 12px`, `align-items: center`): accent spinner (existing CSS, `aria-hidden`) + `STAGE_TEXT[stage]` or `Parsing {Category} ({i}/{n})...`; keep `data-testid="processing-status"` and `data-testid="spinner"` |
| Error | Destructive (existing `FailureBanner`) | `GENERIC_FAILURE_MESSAGE` |
| Duplicate | Neutral-info | `DUPLICATE_BANNER_MESSAGE` |
| Cleared | Neutral-info | `CLEARED_ACK_MESSAGE` (keep `data-testid="cleared-ack"`) |

**Dropzone changes.** The dropzone no longer swaps its prompt for a spinner while busy (D-26 moves progress to the slot). While busy it keeps its prompt, is `aria-disabled="true"`/`aria-busy="true"`, and keeps the existing 0.85 opacity and `not-allowed` cursor. Element, `data-testid="dropzone"` and `aria-label` are unchanged so there is only ever one dropzone in the DOM.
- **Full variant** (first visit): existing styling unchanged (min-height 140px, `2px dashed #888`, radius 8px, bg `#f7f7fa`, padding 20px). Prompt: `DROPZONE_PROMPT`.
- **Compact variant** (slim bar): `min-height: 0`, padding `8px 12px`, `1px dashed #80868b` border, radius 6px, bg `#fff`, prompt left-aligned Body role, full width of the bar. Prompt: `Drop a new export (.zip) here to replace this one, or click to choose it.` Drag-highlight (accent) and focus ring identical to the full variant. Dropping a different zip triggers the existing replace-confirm flow.

**Slim bar chrome:** bg `#f7f7fa`, `1px solid #dadce0`, radius 6px, padding `12px 16px` (same as the Phase 2 `.persistent-bar`). "Imported on {date}" uses Label in neutral `#3c4043`. Buttons "Start over" and "Clear my cached data": Label 14/600, `padding: 8px 16px`, `1px solid #80868b`, bg `#fff`, text `#3c4043`, radius 6px, hover bg `#f1f3f4`, accent focus ring. **Both** are kept (Phase 2 D-17) and both open the one shared `ConfirmPanel` with the identical clear-data copy (Phase 2 D-22). Retain `data-testid="start-over"` and `data-testid="clear-data-control"`; the wrapper keeps `data-testid="persistent-bar"`. The old separate bottom `.persistent-bar` block is removed (it is now inside the slim bar).

**Focus management** (new; required because the panel now opens inside a bar that may have just replaced the button that opened it):
- When `ConfirmPanel` mounts, focus moves to its dismiss button (the safe default).
- Dismiss returns focus to the trigger that opened it (Start over / Clear my cached data / the compact dropzone label for replace-on-drop).
- After a confirmed clear, focus moves to the full-size dropzone (the trigger no longer exists).

### Sticky anchor nav (D-01, D-03, D-04, D-05)

- `<nav aria-label="Dashboard sections" data-testid="dashboard-nav">` containing a `<ul>` (no bullets) of five `<li><a href="#…">` in fixed order: Activity_history, Player_statistics, Payment_history, User_Info, Not yet supported.
- `position: sticky; top: 0; z-index: 1`. Sticky at all widths; it is the only sticky element (the import bar scrolls away).
- Surface: bg `#f7f7fa`, `1px solid #dadce0`, radius 6px, `padding: 8px`. Opaque so scrolled content never shows through. No box-shadow.
- Layout: `display: flex; flex-wrap: nowrap; gap: 0; overflow-x: auto`. **The nav never wraps and never causes page-level horizontal scroll.** At 720px it is expected to fit; at 375px it scrolls inside its own container (all links reachable by swipe and by keyboard Tab, which scrolls the focused link into view natively). Its height is therefore constant (about 56px), which is what makes the single `--nav-offset` correct. Phase 7 may refine the phone treatment.
- Link: `display: block; padding: 8px 8px; border-bottom: 3px solid transparent; border-radius: 6px; white-space: nowrap; text-decoration: none`. No transitions.

| Link state | Text colour | Weight | Other |
|------------|-------------|--------|-------|
| Default (section has data) | `#3c4043` | 600 | |
| Hover | unchanged | unchanged | bg `#dadce0` (see the Color table; amended by W-03, supersedes `#ffffff`) |
| Muted (section is `no-export`, `empty`, `not-loaded`; unsupported block has none or no export) | `#5f6368` | **400** | still a working link |
| Current (`aria-current="location"`) | `#08060d` (muted links keep `#5f6368`) | 600 | `border-bottom: 3px solid #1a73e8` |
| Focus-visible | | | 3px `#1a73e8` outline, offset 2px |

Current wins over muted for weight and underline, so a muted current link reads "lighter text, blue underline, weight 600".

- **Accessible name carries status (D-03):** every muted link contains a visually-hidden suffix span so its name is, for example, `Payment_history, not in this export`. Suffix strings are in the Copywriting Contract. Default links have no suffix. Do not use `aria-label` (it would override the visible text).
- **Links are native `#hash` anchors.** No `click` handler that calls `scrollIntoView`; no `hashchange` listener; nothing is restored from the URL on load (D-04). The URL hash may change.
- **Smooth scroll:** `html { scroll-behavior: smooth }` only inside `@media (prefers-reduced-motion: no-preference)`. Otherwise jumps are instant.
- **Scroll-spy (D-05):** one `IntersectionObserver` over the five section elements is the single source of truth for `aria-current`; clicks do not set it manually. Active section = the topmost section intersecting the band that starts at `--nav-offset` from the top and ends at 40% of the viewport height (`rootMargin: "-72px 0px -60% 0px"`). If no section intersects the band (a long section spans it), the previous active link is kept. Initial active link = the first section. When the page is scrolled to the very bottom (`scrollY + innerHeight >= scrollHeight - 1`), the last link is current (so the short final block can be reached). The observer is created after the sections mount and disconnected on destroy. It runs in every state, including the skeleton, and needs no fallback for reduced motion because it changes no motion.

### DashboardSection (D-07, D-08, D-09, D-10, D-11)

Shell for every section, one card each: `<section id="…" aria-labelledby="{id}-heading" data-testid="dashboard-section-{id}" data-status="{status}">`, `display: flex; flex-direction: column; gap: 8px`, `padding: 16px`, `scroll-margin-top: var(--nav-offset)`. Heading `<h2 id="{id}-heading">` in the Heading role, text = the folder name exactly as written (`Activity_history`, etc., not prettified).

Status comes from one pure function over `ClassifyResult` shared by the nav and the sections, so they cannot disagree (D-08):

| Status | Meaning | Card | Nav link | Body |
|--------|---------|------|----------|------|
| `not-loaded` | no export loaded (skeleton) | greyed | muted | status line: `Drop an export to see this section` |
| `no-export` | supported category absent from the export | greyed | muted | status line: `Not in this export` |
| `empty` | category present, zero parsed rows | greyed | muted | status line: `This export contains no rows for {Category}` |
| `pending` | rows present, dashboard not built yet | white card, `1px solid #dadce0` | default | import summary, then the note (see below) |
| `ready` | dashboard built (Phases 4-6) | white card | default | content snippet, then small import caption |

- **Greyed card:** bg `#f7f7fa`, `1px dashed #80868b`, heading and status text `#5f6368`. The status line is Label 14/600 and is **always visible text**; greyed styling never carries status alone (D-10). No opacity is applied to text.
- **`pending` body:** (1) summary line: `{formatFileCount}, {formatRowCount}` in Body, followed inline by the skip tag when `skippedRowCount > 0`; (2) note in Body `#3c4043`, `Dashboard coming in a later update`. **User_Info override:** its note is `Account details are shown in the header above` (no phase ever builds a User_Info dashboard, so "coming in a later update" would be false; this is a discretion-area refinement of D-09's wording).
- **Skip tag:** `1px solid #f9ab00`, bg `#fef7e0`, text `#8a5a00`, Label 14/600, `border-radius: 999px`, `padding: 0 8px`, `margin-left: 4px`; rendered only when `skippedRowCount > 0`, using `formatSkippedRowCount`. Never "0 rows skipped".
- **`ready` caption (D-09):** after the content, one Label-role line in muted `#5f6368` with the same counts (`{files}, {rows}` plus skip tag) so import diagnostics are never lost. Phases 4-6 provide only the content snippet.
- Per-title absence inside Player_statistics is **not** modelled (D-11).
- Component-level API (prop names, snippet shape) is planner's discretion; the rendered output above is binding.

### Identity header (D-12..D-17, D-21, D-24)

`<section aria-label="Account identity" data-testid="identity-header">`, card with `padding: 16px`, `display: flex; flex-direction: column; gap: 8px`.

**Loaded** (white card, `1px solid #dadce0`), in this order:
1. Nickname `<h2 data-testid="identity-nickname">` (Display 28/600/1.2, `#08060d`). Plain text, wraps, no truncation, no tooltip, no `title`, no aria-label.
2. Caption `As of export` (Label, muted). Not a heading. No export date is shown, because `importedAt` is the import time (D-12).
3. `<dl>` grid (`grid-template-columns: max-content 1fr`, gap `4px 16px`): `Region (per export)` → raw `REGION` value, never mapped to friendly names (D-13); `Account created` → date only.
4. Secondary line `Account ID: {accountRoot}` (Label, muted, `data-testid="identity-account-id"`). Root is an untrusted zip-entry string: plain text interpolation only, wraps.

- **Created date (D-15):** display the date portion exactly as written: the text before the first space or `T` of `CREATED_AT`. No `Date` parsing, no locale formatting, no timezone conversion (the field has no timezone). Example `2015-03-11`. This intentionally differs from the `Imported on Sep 28, 2026` style so the two dates are not confused.
- **Missing values:** any absent or empty nickname, region or created value renders `Unknown` in that slot (D-16).
- **User_Info missing entirely (D-16):** the title (Display) is the account ID, the caption and the `dl` are omitted, the separate `Account ID:` line is omitted (it would repeat the title), and the User_Info section shows its greyed `no-export` state.
- Multiple `Account_Info.csv` rows: the worker selects the row whose `ID` equals the account root, else row 1 (D-17); the UI receives a single 3-field identity and never sees `LOGIN`, `BIRTH_DATE` or `BIRTH_DATE_SRC` (D-18, D-20).

**Skeleton (`not-loaded`)**: greyed card (bg `#f7f7fa`, `1px dashed #80868b`). Title `No export loaded` in Display, colour `#5f6368`, as the `<h2>`; below it one Body line in `#5f6368`: `Drop an export to see the account details`. No caption, no `dl`, no ID line.

`document.title` stays the static `WG Data Export Viewer` in every state (D-21); the nickname appears only in the identity `<h2>`.

### Not yet supported block (D-22, D-23)

Same card shell and heading style as other sections (`id="not-yet-supported"`, heading `Not yet supported`).

| Condition | Card | Nav link | Content |
|-----------|------|----------|---------|
| No export loaded | greyed | muted | status line `Drop an export to see this section` |
| Loaded, zero non-supported folders | greyed | muted | status line `No unsupported categories were detected in this export` |
