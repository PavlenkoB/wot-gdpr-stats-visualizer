<objective>
Fix the three latent Phase 2 client defects that make the approved UI-SPEC state matrix unreachable, and make `IngestClient.result` mean "the last known cached dataset" so the dashboard can stay visible during a replacement and after a failure (D-27).

Purpose: the identity header (IDENTITY-01) and every section must remain on screen from the cached dataset across processing, duplicate and error states, and a return visit must never hang on a spinner. All three defects were reproduced against the real class in RESEARCH Q2.

Output: an amended `worker-client.svelte.ts` and unit tests for each behaviour. No component changes here (03-04 and 03-06 consume the new semantics).

Decisions implemented here: D-26 and D-27 (state side), D-28 (cache-check failure never leaves the spinner), Phase 2 D-13 (replace confirmation restored for every state that displays a dataset). Support for SC4 of the phase.

Requirement mapping note: SC4 has no dedicated requirement ID. This plan is mapped to IDENTITY-01 because the identity header is driven by the cached result this plan keeps alive, including on the return-visit and failure paths.
</objective>

- Two small additions beyond the RESEARCH list, both found while tracing and both covered by tests: (a) a worker `error` reply to a confirmed clear no longer leaves the UI stuck in confirm-pending; (b) cancelling a confirm that began from `duplicate` or `error` returns to `done` so the old notice does not reappear.
