<objective>
Close the classification half of CR-01 / W-1 (01-REVIEW.md CR-01, 01-VERIFICATION.md W-1): a top-level folder that is not a recognized category but holds one beneath it must make the importer fail closed instead of being filed as an unknown category beside a stray recognized folder.

Defect, reproduced on the working tree: `analyzeExport(['123/User_Info/Account_Info.csv', '123/Activity_history/a.csv', 'Clans/b.csv'])` returns ok with `accountRoot: ''`, `Clans` as known-deferred and the real account folder `123` as an `unknown` category. The worker then parses `123/User_Info/Account_Info.csv` under category `'123'`, whose name is not User_Info, so the folder-name strip never runs and LOGIN and the birth columns would be written to IndexedDB. Before plan 01-07 put the rootless read first, the same zip returned `no-single-root`, which fails closed.

Purpose: restore the fail-closed property the privacy guarantee depends on, with the smallest rule that closes the reproduced shape and its two siblings (the transparent-wrapper retry and a bounded-depth nest). The rule applies ONLY where the archive is being read as rootless, because that is the only place the claim "there is no account folder" can be falsified by a sibling folder that looks like one.

Layering: this plan is layer 1. Layer 2, plan 01-13, keys the column strip on the header name so that shapes this plan deliberately keeps accepting (a real account root with `Weird/User_Info/...` beneath it, a nest deeper than the bound) still never persist the email.

Output: a hardened `src/lib/worker/classify.ts`, one new fixture builder, a worker-level end-to-end regression test, and a unit describe. No other source file changes.

Tracer exemption: not needed. Task 1 IS the tracer: it drives the defect from zip bytes through the real worker, the classifier and Dexie, and proves the fix on that one path before Task 2 expands the rule.
