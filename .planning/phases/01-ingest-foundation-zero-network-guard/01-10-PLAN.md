<objective>
Close two advisory findings (IN-03, IN-04) by tightening documentation and a dev-driver comment, with no source-of-truth changes:

1. **IN-03 (dev-only):** `.claude/skills/run-data-export-viewer/driver.mjs` line 74 launches Chromium with `args: ['--no-sandbox']`. The flag is required for sandboxed agent runtimes where the agent process is itself sandboxed and a second sandbox layer prevents Chromium from launching. It is a dev-driver-only convenience — the shipped app never uses it (the app has no Chromium at all). Add a one-line comment above the call in `driver.mjs` and a new Gotcha entry in `SKILL.md` so a future contributor does not mistake the flag for a runtime concern.

2. **IN-04 (docs):** README.md's Quick start section currently says "For local development with HMR (no CSP meta applied): pnpm run dev". That sentence exists but does not explicitly tie it to the PLATFORM-02 zero-network assertion. A future contributor who runs `pnpm run dev` and then wonders why the zero-network spec doesn't fire is missing the link. Strengthen the sentence so the relationship to PLATFORM-02 is explicit.

3. **WR-05 doc drift** (incidental, not in this plan's gap_ids but the same doc area): `SKILL.md` still carries the Gotcha "`pnpm run test:e2e` hangs after the last test passes" with the explanation that the hang is caused by `webServer.command: 'pnpm run build && pnpm run preview'`. Plan 01-09 verified that `playwright.config.ts` already uses `./node_modules/.bin/vite build && ./node_modules/.bin/vite preview` (direct binary, no pnpm wrapper) and that `tests/unit/webserver-teardown.test.ts` is the regression guard. The Gotcha is stale. Reduce it to a one-line cross-reference to the regression test rather than a live warning.

Output: documentation-only changes in README.md, .claude/skills/run-data-export-viewer/SKILL.md, and a one-line comment in .claude/skills/run-data-export-viewer/driver.mjs. No source files in `src/` are touched. No test files are touched. No CI configuration is touched.
