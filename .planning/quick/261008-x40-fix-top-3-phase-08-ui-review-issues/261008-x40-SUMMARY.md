## What was done

1. **Palette (tracer).** `#3c4043`, `#5f6368`, `#08060d`, `#1a73e8` replaced by `var(--text)`, `var(--muted)`, `var(--ink)`, `var(--focus)` in 28 components (comments included). The blue hex now exists only as the `--focus` declaration. Guard observed red first (ChartTooltip.svelte and MonthlyBarChart.svelte in the grey offender list), then green. The finance e2e frame spec and the contrast frame check now expect the muted zero line (`rgb(92, 92, 92)`); `chartStroke` resolves `var(--name)` through app.css.
2. **Type scale.** `:root` 16px to 14px; 28 explicit 16px declarations to 14px; spend headline 28px to 26px / 1.3; one `button, input, select, textarea { font-family: inherit; font-size: 14px }` rule after `body`. The phase 5 floor guard now judges `rem` against a named 14px root constant. A rendered sweep helper (`offScaleText`) was added to the existing `(panes)` test (Overview and all seven panes) and `(phone-screens)` test (list and detail at 375px); it reports no visible element or control off the scale. Sanity-checked non-vacuous by temporarily setting the root back to 16px (it listed the skip link and every list row), then restoring.
3. **Footer.** Tightened paddings (product label 8px top, kbd-hint `4px 20px 0`, identity header `4px 20px 4px` / gap 4px, slim import bar `8px 20px`, persistent bar gap `4px 16px` / margin 8px) and `.pane-list .import-region { position: sticky; bottom: 0; background: var(--list) }` inside the existing 900px block. Assertions appended to `(empty-state)`: at 1280x800 start-over, clear-data-control and dropzone fully in the viewport and no row under the footer; at 1280x600 the same three controls. Red observed first (dropzone viewport ratio 0.19). Viewport restored to 720 afterwards. Screenshots at 1440x900, 1280x800 and 375x812 reviewed: nothing cramped.
