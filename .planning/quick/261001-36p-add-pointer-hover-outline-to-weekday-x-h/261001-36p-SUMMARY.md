## Planner decisions (as executed)

1. **Overlay construction.** `hoverIndex` (`$state.raw<number | null>`) is set in `onPointerOver` from `found.index` and cleared in `onPointerOut` under the existing `relatedTarget` guard, beside `onTip(null, null)`. `hoverCell` is a `$derived` lookup in `model.cells`. Two rects (`hover-ring`, `hover-ring hover-ring-inner`) are rendered after the row groups and before the keyboard ring block, so the keyboard ring stays last. Geometry is the keyboard pair's exactly (cell+3 at -1.5, cell+7 at -3.5), `aria-hidden="true"`, no `data-*`, `tabindex` or `role`. The stylesheet rules are shared selector lists (`.focus-ring, .hover-ring` and `.focus-ring-inner, .hover-ring-inner`), so one declaration list serves both rings and nothing animates.
2. **Four HourGrid differences.**
   - **svg overflow (the one behaviour change beyond hover):** the svg rule gained `overflow: visible`. HourGrid's svg previously used the default `overflow: hidden`, which cropped the ring's overhang on the bottom row and last column where cells sit flush with the svg edge. This is paint only (no layout change) and it also un-crops the existing keyboard ring on those edge cells.
   - No year blocks and no `isInYear` guard: one svg, 168 fixed indices, `hoverCell` is `model.cells[hoverIndex] ?? null`.
   - The inline `onpointerdown` arrow on the svg was left exactly as it was: it clears `keyboardFocus` only and does not touch `hoverIndex`, since a press does not move the pointer.
   - The hover pair carries `aria-hidden="true"` to match the keyboard pair in this file.
3. **No shared helper with the calendar.** `CalendarHeatmap.svelte` is not modified (its unit contracts count `class="focus-ring` / `class="hover-ring` in its own source).
4. **Escape dismisses the tooltip only.** The ring is pointer position, so it stays until the pointer leaves, as in the calendar. Not tested.
