## Decision made by the planner (record it in the SUMMARY)

The orchestrator asked for a CSS-only `:hover` stroke on the cell rect "if the component's existing focus styling is CSS-based". It is not. The keyboard ring is a state-driven two-rect SVG overlay drawn last inside each year svg, and `.cell` deliberately sets `outline: none`. The component documents why: an SVG rect paints with its own geometry, so a stroke on a cell is covered by the cells to its right and below. Worked through for a hover stroke: the cell is 10px on an 11px pitch, a 3px stroke centred on the edge reaches 1.5px outside it, and the next cell's 1px white separator starts 0.5px outside its own edge, so roughly 1px of the 1.5px is painted over on the right and bottom sides only. The result is a lopsided ring. There is no CSS z-index for SVG children. Matching the existing pattern therefore means the same overlay construction, driven by pointer position instead of keyboard state. This is per the orchestrator's own "pick whichever matches the existing pattern" clause and the user's "match the same outline treatment the keyboard focus uses".
