<objective>
Close the persistence half of CR-01 (01-REVIEW.md CR-01 fix layer 2): make the LOGIN / BIRTH_DATE / BIRTH_DATE_SRC strip depend on the column NAME in the parsed row, not on the folder the file happened to be filed under.

Defect: in `src/lib/worker/ingest.worker.ts` the choke point decides whether to sanitise a row with `isUserInfoCategory(entry.name)`, a folder-name test. Any export shape that files an Account_Info file under another category name (a renamed folder, a nest below an unknown folder, a misfiled copy, a shape the classifier misreads) bypasses it, and the email and birth data would be written to IndexedDB. Plan 01-11 closes the reproduced classification path; this plan makes the guarantee independent of classification being right.

Purpose: 03-CONTEXT D-18 says the three columns never rest in IndexedDB. The enforcement point must be keyed on the thing D-18 names, the columns. The planning input that fixed this scope widens D-18's wording from "User_Info only" to "any row that carries one of those headers"; this plan implements that widening and records it in the SUMMARY (03-CONTEXT.md itself is not edited).

Scope decision, stated deliberately: the full sanitiser also drops the `__parsed_extra` overflow bucket. It is triggered ONLY for rows that carry a deny-listed header (or live in a User_Info-family folder). Calling it on every row of every category would also strip overflow cells from files that have no sensitive header, which narrows Phase 2's store-everything rule beyond what D-18 covers.

Output: one small exported predicate, one changed call site, two fixture builders, worker-level and unit tests.

Tracer exemption: not needed. Task 1 is the tracer: one misfiled file driven from zip bytes through the real parse loop, the strip and Dexie.

Locked decisions (01-CONTEXT.md D-01..D-17): none is reversed. D-09 (worker message contract frozen) is preserved: no message shape changes.
</objective>
