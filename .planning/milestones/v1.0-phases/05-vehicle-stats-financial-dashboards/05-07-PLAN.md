<objective>
Wire the four pure builders to the page's data path: one typed query contract, an on-demand worker answer from one Dexie snapshot, per-file presence facts recorded at import, and a channel-scoped client so several blocks can ask at once.

Purpose: plans 05-10 to 05-15 each render one block from one channel. Phase 4's PlaytimeClient supersedes every pending query when a new one is issued, which would leave two of three simultaneously mounted blocks loading forever (RESEARCH Pitfall 1). Presence facts matter because D-02 and D-05 distinguish a file that is absent from a file that is present with no rows, and a header-only file leaves no row behind to say it was there.

Output: the message contract, `QueryClient`, `data-queries.ts`, `readRowsByFile`, `meta.files`, the worker handler, the IngestClient wiring, and tests that drive the real worker, the real Dexie database and the real client.

Decisions implemented here: D-02 (per-sub-block not-in-export versus no-rows needs file presence), D-05 (title states need the same facts), D-28 (an answer for a replaced dataset is never applied, which is what lets blocks reset on replace and Clear); Claude's discretion: on-demand queries with an in-worker memo, no stored aggregates, no Dexie version bump.
</objective>

## Planner assumptions and flags

- **Gap found while planning, resolved here.** Neither RESEARCH nor the UI-SPEC noted that the rows table cannot tell an absent file from a header-only one, yet D-02 and D-05 show different sentences for them. Presence is therefore recorded at import (meta.files). This is the one new stored field; it needs no Dexie version.
- **Legacy caches.** A cache written before this plan has no files list. Every file lookup then answers as present, so the block says "no rows" (which is true whether the file is absent or empty) instead of the "not in this export" claim it cannot support. Phase 4 made the same asymmetry explicit for sessions.
- **Worker error detail.** Phase 4 sent the error's name and message. Phase 5 sends the name only, because a message from a builder or the BigInt constructor can echo a cell. The client already never renders the detail.
- **Memo.** Small and bounded by design; the key is the channel plus the canonical JSON of the query, and the stored importedAt must equal the snapshot's. Memo is a latency convenience and is covered by a freshness test, not relied on for correctness.
- **No stored aggregate.** If the 50,000-row browser budget in plan 05-16 fails, the documented fallback is stored aggregates on the meta record (the Phase 4 pattern); that is not planned here.
- **Task 1 has five files** because the contract, the reader, the dispatcher and the handler cannot be exercised separately; the dispatcher already covers all four channels so no channel is left unanswered.
