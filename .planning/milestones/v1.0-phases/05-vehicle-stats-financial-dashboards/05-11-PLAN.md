## Planner assumptions and flags

- **Tooltip instance per container.** UI-SPEC section 8 says one shared tooltip. Phase 4's PlaytimeCharts renders its own, and its browser and source-contract tests locate chart-tooltip unscoped, so a second element with that id would break them. The Financial charts therefore share one instance with a different test id, recorded in plan 05-08's spec amendment. Phase 4 files stay untouched except one source-contract assertion that read the literal test id, which now reads the prop default.
- **Presentation attributes only.** Bars use class selectors in the component stylesheet (fill from the custom properties); no style attribute, no style directive, no SVG style element, because the CSP has no style-src unsafe-inline.
- **Ring node budget.** The two rings add at most four nodes, inside the +40 slack of the 3m+40 bound.
- **Data attribute values are numbers or YYYY-MM text only**, never untrusted strings, and no selector concatenates a data attribute.
- **Task 2 touches six files**, five of them small: the tooltip testId and extra, the model's optional field, the owner state in the card body and one Phase 4 assertion.
