<objective>
Ship the privacy-critical, worker-side half of the identity story: strip `LOGIN`, `BIRTH_DATE` and `BIRTH_DATE_SRC` from User_Info rows before they reach IndexedDB (D-18), compute a three-field identity in the worker (D-17, D-20), persist it on the dataset meta record and replay it on `done`, `duplicate` and `cache-status`, and wipe every Phase 2 cache that still holds the email (D-19).

Purpose: IDENTITY-01 says the dashboard opens on whose account it is while the email stays out of the page. That guarantee is only real if the email never leaves the worker and never rests in IndexedDB. Everything the UI plans (03-04 onward) render is read from the `identity` this plan produces.

Output: `identity.ts` (pure), the extended message and meta contracts, the Dexie v2 upgrade, the worker wiring, and the fixture builders that every later unit and e2e test in this phase reuses.

Decisions implemented here: D-17, D-18, D-19, D-20 (and the D-16 fallback trigger via `identity: null`). D-21 is enforced at the worker end (no identity or row value is ever logged).
</objective>

## Planner choices (PATTERNS.md versus RESEARCH.md)

03-PATTERNS.md was written without RESEARCH.md. Where they differ, RESEARCH.md wins, and the choices are stated here so the executor does not "correct" them back:

1. Strip keyed on a normalised key (`trim().toUpperCase()` with an optional `_N` suffix), on a case-insensitive category test, and on `__parsed_extra`, NOT on the literal `entry.name === 'User_Info'` plus exact key deletion that PATTERNS proposed. The literal form leaks for `user_info`, padded headers, duplicate headers and overflow cells (RESEARCH Q3, probed).
2. `AccountIdentity` fields are `string | null` (RESEARCH), not optional strings (PATTERNS). `null` for the whole identity means "no User_Info row parsed" and triggers the D-16 fallback header.
3. The Dexie upgrader must await both `clear()` calls (RESEARCH Q1, probed). PATTERNS' `clear() && clear()` one-liner would not await the second call.
4. Identity plumbing uses one `resultFromMeta` helper for both replays (RESEARCH Q3) rather than editing two literals.

## Reversibility gate (D-18)

D-18 is rated one-way in 03-CONTEXT.md: once stripped, the columns cannot be recovered without re-importing the zip. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| zip file contents to worker parse loop | Untrusted CSV headers and cells (any column name, any casing, extra cells) enter the worker |
| worker to IndexedDB | What is written here persists on the user's device indefinitely |
| worker to main thread (postMessage) | Only the three-field identity and the category counts may cross; the row data must not |
