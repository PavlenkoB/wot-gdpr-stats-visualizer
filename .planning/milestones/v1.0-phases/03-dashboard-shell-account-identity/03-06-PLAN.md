## Planner choices

- `persistent-bar` is the slim variant's meta row (imported-on text plus the two buttons); UI-SPEC says the wrapper keeps that id and the old bottom bar is removed. It exists only in the slim variant, which the persistent-dataset spec relies on (count 0 on first visit).
- The notice slot never uses flex `gap` on the import element: notices and the meta row carry their own 12px bottom margin so an empty slot adds no space (UI-SPEC notice-slot rule). FailureBanner's bottom margin changes from 16px to 12px to match.
- `Dropzone` loses its `statusText` prop; the processing text now flows through the notice slot. The spinner styles move with it (duplicated, not extracted, as UI-SPEC already notes).
- The ConfirmPanel is passed into ImportBar as a snippet so App keeps the copy selection (`confirmCopy`) and ImportBar stays presentational.

## Flagged planner assumptions

- Duplicate notice reachability: the replace confirmation (Phase 2 D-13) happens before the worker's hash check, so an identical re-drop first shows the confirm panel; the notice appears after the user confirms. Skipping the confirm for identical bytes would need a main-thread hash and is out of scope.
- The cache-check window is exercised by delaying the worker script with a route handler (no extra network request is made; the request is only held back), because the worker performs the IndexedDB read.
