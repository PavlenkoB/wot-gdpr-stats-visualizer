**Result:** 61 threat IDs (77 register rows across 17 plans), **all 61 closed**, `threats_open: 0`. No escalations. Two audit passes: the full audit (58 closed, 3 open below the high threshold) and a targeted re-audit after the code-review fixes, in which T-06-23 closed and T-06-17 / T-06-36 were found only partly fixed (an https->http->https redirect chain bypassed the first fix); that gap was then closed by a per-hop https check (see T-06-17).

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Export file to worker | The Wargaming export (CSV cells, IP and time columns) is untrusted input parsed in the pipeline worker | Raw login rows, IP addresses (sensitive) |
| Worker to main thread | Typed messages only; aggregates and views, never raw rows or full addresses before reveal | Counts, masked/canonical addresses, country codes |
| Main thread to DOM | Masked by default; one global reveal control; address-shaped account-record text reads "not readable" | Displayed IP strings (sensitive) |
| Page to network (one sanctioned request) | The opt-in city file, same-origin, main thread, user-initiated (src/lib/geo/city-fetch.ts) | Nothing from the user's data; a GET for one static asset |
| Downloaded city file to worker | Untrusted bytes: length and SHA-256 verified before inflate and decode, size caps, fixed error text | City place table (public data) |
| Build time to shipped artifacts | DB-IP downloads, world-atlas, d3-geo and topojson-client run only in Node build scripts | Public geo data; devDependencies only |
