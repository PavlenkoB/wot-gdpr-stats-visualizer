# Phase 06 Plan 09: City dataset pipeline Summary

**A DB-IP city CSV streamed into one 11.88 MB pre-gzipped container by a Node build script, and a worker that turns those posted bytes into a ranked CityView — with the city fetch decided as main-thread so the CSP actually governs it.**

## Accomplishments

- **The city dataset now exists end to end on the data side.** `scripts/geo/build-city-dataset.ts` streams the DB-IP city CSV (7.8 M source rows) into growing typed-array columns and emits ONE pre-gzipped container plus `manifest.json` under `public/geo-city-data/`. A single file, not shards: shard requests would tell the static host which IP prefixes the account used (D-13). The asset is gitignored, shipped by the build, never committed.
- **The worker side is complete and hardened.** The worker accepts posted city bytes, sniffs the gzip magic, inflates under a decompressed-size cap, checks the manifest sha256, validates the container (magic, version, kind, counts, bounds), decodes only the address families actually present among the listed addresses, and answers a CityView. Every failure is the single fixed detail `city data invalid` — no size, offset or byte ever appears in it.
- **The real pipeline was exercised once, and the numbers are measured.** The measured figures below CORRECT RESEARCH's estimate, and the correction matters for Phase 7's caps.
- **The fetch-location decision is recorded, with the evidence that decided it.** option-a, recorded in 06-CONTEXT.md, with D-16's unenforceable clause annotated rather than repeated.

## TDD Gate Compliance

**The TDD RED could not be machine-validated. This is a defect in the GSD gate tool, not in this plan.**

`gsd_run check tdd-red-evidence` returned `INVALID_RED` twice, on two different reporters:

- **TAP** → `zero_tests_discovered`
- **JUnit** → `no_target_test_failure`

The cause is in the classifier itself, `.claude/gsd-core/bin/lib/tdd-red-evidence.cjs`:

- It parses only `node --test` TAP output (a `# tests N` line plus unindented `not ok N - <name>`), which vitest 5's own `--reporter=tap` does not emit — vitest nests every test inside a file-level `not ok`, which the parser reads as a load crash. This half of the defect is already recorded in STATE.md since **04-01**.
- Its Surefire path is `const name = /name="([^"]*)"/.exec(tagText)?.[1] ?? '';` (line 73). That pattern matches **inside `classname="…"` first**, because `classname=` contains `name=`. So every Vitest test is reported under the name `file#file` — the file path repeated — and the target test name can never be found in the report. Line 74 reads `classname` correctly, three lines too late.

**The RED was genuine by inspection.** Four distinctly-named tests failed on assertions about the planned behaviour:

- a wrong manifest sha256 and a wrong declared length both answered a full CityView, because the handler read neither field;
- `--download` was an unknown flag, and a real build wrote no licence note.

**The raw failure text is committed** at `.planning/phases/06-login-ip-history-offline-geolocation/06-09-red-evidence.{json,xml}` in `afb5269`. The JUnit report itself is the proof: `tests="7" failures="4"`.

**This reproduces on any Vitest project, and it is worth filing separately in GSD because it is not plan-specific.** Plan **06-08 hit the identical defect independently**, and STATE.md has carried the TAP half of it since 04-01. Two plans reaching the same wall by different routes is what makes it a tool bug worth fixing rather than a local note: the fix is to prefer `classname` when both attributes are present (or to parse the attributes rather than regex the tag text), plus a vitest-aware TAP path.

**Until it is fixed, the git-log RED gate is the machine check that works in this repository:** `git log -E --grep="^test\((0*6)-(0*9)\):"`.

## Two design facts that took measurement to establish

These are the two a future reader would otherwise get wrong, so they are recorded here rather than left in the code:

- **An empty city name is KEPT, not skipped.** The database describes those prefixes — it has a country and a region — and says the city is not recorded. Dropping the rows would turn that into `no record at all`, telling a user a falsehood about a prefix the database does describe. The row is kept and the address is counted in `noCityAddresses` instead, which is the honest sentence: a country we know, a city we do not.
- **A place is encoded as `CC` <TAB> `state` <TAB> `city`,** not as a comma-joined string, **because a city name may contain a comma.** The fixture contains one such city and `parseCityLine` reads it through the existing quoted-field splitter, which also handles an escaped quote.

## Decisions Made

### The city file is fetched on the MAIN THREAD (option-a) — `67c8c2a`

D-16 asks for a CSP that "allows only same-origin for this one asset". **That is not an enforceable property of a CSP**, and the measurement says so plainly:

- A meta CSP with `connect-src 'none'` **blocked a main-thread fetch, but a module-worker's fetch returned 200**, and Playwright's context request event recorded the worker request. So the CSP is **blind to worker traffic** in this setup.
- `connect-src 'self'` is a **host source**: it cannot be path-restricted to `geo-city-data/`. Widening it admits any same-origin path, not one file.

**The choice: option-a.** The main thread fetches (`src/lib/geo/city-fetch.ts`, the single exempt module), the `ArrayBuffer` is **transferred** to the worker, and the CSP becomes `connect-src 'self'`. Cancel is a plain `AbortController`. **Plan 06-11 is already written for this shape and needs no revision.**

**Why not option-b (fetch inside the worker, `connect-src` stays `'none'`).** Under option-b the CSP text would have stayed `none` while governing **nothing** — the one network call this product is permitted to make would have been the one call the policy cannot see. The strongest-looking guard in the project would have been theatre, and it would have bought a lint **exemption inside `src/lib/worker/**`** — the exact directory that holds the raw rows and must never be able to reach the network. Under option-a the CSP genuinely governs the one sanctioned fetch and `src/lib/worker/**` keeps its **absolute** lint ban with no exemption anywhere in it.

**The cost, stated honestly.** `connect-src` widens from `'none'` to `'self'` for the whole page. **That is defence in depth only and must not be mistaken for the guarantee.** The actual enforcement of "no network" is unchanged and is the same in both options: the **ESLint network ban** on `src/lib/geo/` and `src/lib/worker/`, and the **Playwright request assertions** that plan 06-14 extends. Anyone who reads the widened CSP as the guarantee has read it backwards.

**The corollary, which reaches further back than this plan.** Because the `connect-src 'none'` this project has been shipping was **never governing worker traffic either**, any belief in this repository that rested on it needs re-checking. It is not a regression — the ban that actually held was always the lint ban — but the CSP must not be cited as evidence that no worker can reach the network.

### The place sort lives in the writer

The plan's Task 1 step 3 called for "a second pass over the buffered columns" that remaps every id after the place keys are sorted — the remap is exactly what buys the 11.88 MB. Doing that in the caller would have made it a convention every future caller must remember. It is done inside `encodeRangeTableColumns` instead, so the property belongs to the **writer** and no caller can produce a table with unsorted place ids by forgetting.
