## Layouts & Breakpoints

### Desktop (≥ 900px)
- **Shell:** wrapping flex row, `flex-wrap: wrap`, `min-height: 100vh`
  - List pane: `flex: 1 0 320px`, light background, sticky top/100vh when ≥900px
  - Detail pane: `flex: 999 1 560px`, `min-width: 0`, white background, `padding: 32px 40px 64px`
  - **Visual hierarchy (desktop):** List pane top (identity header) anchors the hierarchy; selected row with its 3px ink bar acts as the primary focal point; detail title (26px/600 ink) is secondary focus
- **List structure:**
  - Top: identity header (nickname 26px/600, account meta, "Account created … · Imported …")
  - Middle: nav `<ul>` with rows (min-height 56px, select with `aria-current="true"`)
  - Bottom: "Not yet supported" footer row, then compact drop target + actions
- **Row anatomy:** `<button>` inside `<li>`, grid layout with title left (14px/600 ink), headline right (14px/600), summary below (14px muted). Borders 1px #dcdcdc. Selected: #e0e0e0 bg + 3px inset ink bar. Hover: #ececec.
- **Row states:** available (normal), muted (unavailable, title/headline in #5c5c5c), footer (compact, "4 folders" badge)

### Tablet (480px–900px)
- **Layout:** stacked (list above, detail below), no sticky position
- **List pane:** full width, white background (not gray), rows still 56px
- **Detail pane:** full width, same padding as desktop
- **Visual hierarchy (tablet):** Identity header remains at top; detail title becomes primary focus when scrolled into view

### Phone (≤ 480px)
- **Two screens (no router):** list screen, then detail screen
- **Shared state:** section selection held as component state
- **List screen:**
  - Identity header at top (white background, full width)
  - List rows: 64px tall (title + summary left, headline right, chevron indicator)
  - "Not yet supported" footer: 52px
  - Actions (drop target, "Start over", "Clear my cached data"): 48px each
  - **Visual hierarchy (phone list):** Identity header at top; selected row's chevron indicator and ink text are the focal points
- **Detail screen:**
  - Top bar: 48px high, back button "‹ Sections" left-aligned, section title centered (18px/600 for Display role collapse to Heading)
  - Content: scrollable, Overview cards stack 1-up, stat tiles become 3-up row (18px numerals)
  - Charts (calendar, hour-grid) inside horizontally scrolling boxes
  - "About this chart" disclosure: 44px summary height
  - All touch targets ≥ 44px (maintained by existing `src/app.css` rule)
  - **Visual hierarchy (phone detail):** Back button and title bar are the primary focus; first card content is secondary

## Amendment A-1 (G-08-3): measured chart width

**Cause.** The charts were drawn at fixed svg widths, so at a 1280px window they covered only 60 to 72 percent of the 879px detail pane (UAT test 3, gap G-08-3).

**Rule.** Each chart measures the width of its own container with `bind:contentRect` (the block its parent sizes, never the svg, so there is no feedback loop) and recomputes its layout so that the svg width equals the container width at every pane width above the floor. The svg stays a fixed pixel size with no `viewBox`, so axis text stays 14px and is never scaled.

**Floor.** Today's geometry is the minimum. Phone widths and very long month spans therefore keep their own horizontal scroller inside the chart box, exactly as before. A measured width of zero, a non-finite or a negative number counts as "not measured" and yields today's geometry.

**No upper bound.** There is no maximum width. The charts keep reaching the pane's right edge however wide the window gets; only the size of a single mark is capped (below).

**Reserve.** The right edge of a filled chart keeps 4px (`CHART_RING_PAD_PX`) so the 3px focus ring and its 1px outer stroke are not cut off.

**Bar chart.** The slots fill the plot, with the remainder spread in whole pixels. The drawn bar is capped at 32px and centred in its slot. This mark-size cap overrides plan 05-22's 16px pitch cap on the measured path only; the unmeasured path is unchanged. X-axis labels keep today's stride.

**Heatmaps.** The columns fill the plot by the same edge rule, with cells within 1px of square. The cell height is capped by a row pitch of 24 for the calendar and 48 for the weekday-by-hour grid, so at very wide panes the cells become wider than tall while the columns still fill the pane.

**Superseded statements.** This replaces the fixed-width wording in the "Chart geometry (unchanged from Phase 4-6)" exception and in the "detail charts (calendar, hour-grid, tables)" overflow row. It adds no test id, no media query and no token.

**Checked at.** 1280px, 800px, 375px and a wide window (2000px or more).

## Amendment A-2 (quick 261008-x40): type base, palette tokens and the sticky footer

**Cause.** The first 08-UI-REVIEW (16/24) found off-token greys, 16px and 13.33px text outside the declared scale, and the list-pane footer actions clipped at the 800px fold.

**Type base.** The page root is 14px, so every element that declares no size is the Body role. Native controls get an explicit 14px from one element-level rule in `src/app.css` (`button, input, select, textarea`, outside the phone block), because a native control ignores the inherited size. Every `font-size` under `src` is one of 14, 18, 26 or 30px. The Payments spend headline is the Display role (26px, line-height 1.3) instead of 28px.

**Palette.** Greys are read only through `--text`, `--muted` and `--ink`, including the monthly chart zero line, which is now `--muted` (`#5c5c5c`) and supersedes the 05 zero-line hex. The blue hex exists only as the `--focus` declaration; every focus outline, hover or focus ring stroke, the spinner arc and the Dropzone drag border read `var(--focus)` (the computed colour is unchanged).

**Footer.** At 900px and above the list-pane import region is sticky at the bottom of the scrolling pane with the list background, so Start over, Clear my cached data and the compact dropzone stay on screen at any window height. The list-pane paddings are tightened on the 4px scale (product label, keyboard hint, identity header, slim import bar).

**Checked at.** 1280x800, 1280x600 and 1440x900.

## Amendment A-3 (quick 261009-0qw): login label placement, one phone block, keyboard finding

**Cause.** The re-audit of 08-UI-REVIEW (18/24) read the Login history tiles as disagreeing with the table, the phone-width rules as split across nine files, and the keyboard selection as lagging one press. Two of the three were not the defects described.

**Login history.** The tiles count login rows only, and the pinned Account record row is never counted in a tile, the map, a list or the count line (Phase 6 D-02), so Countries 0 beside an Account record that shows a country is correct. What was out of reach is the sentence that labels the row: the Account record note now sits directly above the IP table, between the count line and the table, instead of under it and below the fold. This supersedes the 06-UI-SPEC "Notes under the table" placement for that one note only; the element, its test id, its condition and its wording are unchanged. An end-to-end assertion ties the Countries tile to the distinct named country cells of the login rows.

**One phone block.** The phone block in `src/app.css` carries every phone-width rule in the project; no component stylesheet declares a phone-width query, and a source guard pins zero in components and one in `src/app.css`. Each moved selector is `.shell`-prefixed on the component's own unique hook (a root class or a test id), so it is strictly more specific than the scoped rule it replaced and never depends on stylesheet order. One exception: the list-row background is written with a single type selector above the base row so it stays below the hover and selected rules. Two root class tokens were added as hooks (`playtime-summary`, `login-summary`). Computed styles and bounding boxes were identical before and after at every width listed below, on the dev server and on a production build.

**Keyboard.** Once an export is loaded, selection follows focus on every `j`, `k` and arrow press, including the clamp presses; the shell e2e test now asserts it after each key in one non-retrying read. With nothing loaded the selection is pinned to Overview by design (Phase 8 D-05), and a first import resets it to Overview (D-03).
