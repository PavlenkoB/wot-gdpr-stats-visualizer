<objective>
Harden the request seam plan 04-01 introduced so the Playtime block can never hang and can never show an answer to a question it is no longer asking. The tracer proves the smallest new path: a worker error while a query is pending resolves that query as an error outcome through the real `IngestClient`. The expansion tasks add latest-wins supersede, unavailable and throwing posts, and a regression suite that pins the ingest state machine against every playtime message.

Purpose: `PlaytimeClient` is the only place stale answers are neutralised. Plan 04-08's component leans on its `superseded` outcome and on error outcomes to drive the `updating` and `error` states.

Output: extended `src/lib/playtime-client.ts` and `src/lib/worker-client.svelte.ts`; new `tests/unit/playtime-client.test.ts`; regression cases in `tests/unit/ingest-client.test.ts`.

Decisions implemented here: D-03 (selection changes in flight, latest wins, per UI-SPEC updating state), D-02 (a failed query never fails the import; the dataset is untouched).
</objective>

## Artifacts this phase produces

Symbols added or changed by THIS plan (04-07). Plan 04-08 consumes them and must not rename them.

- `src/lib/playtime-client.ts` (extended):
  - `PlaytimeOutcome` gains a third variant `{ kind: 'superseded', queryId }`; the existing `result` and `error` variants are unchanged.
  - `PlaytimeClient` constructor becomes `(post, isAvailable?)`, where `post` is the same function plan 04-01 passes and `isAvailable` is an optional probe defaulting to always available.
  - New members: `failPending(detail)` and a read-only `pendingCount` (for tests).
- `src/lib/worker-client.svelte.ts` (extended): the `playtime` field is constructed with an availability probe that reads the broken-worker flag; `onerror` and `onmessageerror` call `playtime.failPending` with the fixed details `worker error` and `worker message could not be deserialized`.
- `tests/unit/playtime-client.test.ts` (new); new cases in `tests/unit/ingest-client.test.ts`.

## Planner assumptions and flags

- **Fixed details.** The two failPending details are fixed strings on purpose: an error event's message can carry file paths, and Phase 3 D-21 keeps such text out of anything user-visible.
- **Supersede on issue.** An older query is resolved as superseded when the newer one is issued, not when a reply arrives, so a component awaiting the older promise is released even if the worker never answers it.
