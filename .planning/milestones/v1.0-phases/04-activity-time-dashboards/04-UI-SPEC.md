Accent reserved for (explicit list, nothing else, unchanged from Phase 3):

On a cell the ring is drawn as an SVG outline on top of the cell (3px accent stroke with a 1px `#ffffff` stroke inside it), not as a CSS outline, so neighbouring cells cannot cover it. The same ring is also drawn on the heatmap cell under the pointer, in both the calendar and the weekday by hour grid; hover is pointer position and is never treated as keyboard focus.
3. Processing spinner arc
4. The 3px bottom border under the current nav link

Data ramp, the only new colours. Single hue (teal), lightness strictly monotonic, so more play is always darker and never depends on hue:

| Level | Meaning | Value | Contrast on `#ffffff` | Ratio to previous step |
|-------|---------|-------|-----------------------|------------------------|
| 0 | no play | `#eef0f2` | 1.14 | — |
| 1 | lowest fifth of active days (or cells) | `#b2dcd4` | 1.49 | 1.31 |
| 2 | | `#7cc7bc` | 1.95 | 1.31 |
| 3 | | `#43a89c` | 2.87 | 1.47 |
| 4 | | `#1f7a74` | 5.13 | 1.79 |
| 5 | top fifth | `#0d4f4c` | 9.38 | 1.83 |

Ratios were computed with the WCAG formula in `tests/helpers/contrast.ts` (figures above), not estimated. The level boundaries never carry meaning by colour alone.

| Hover ring on heatmap cells | The same 3px `#1a73e8` outside a 1px `#ffffff` inner stroke as the focus ring, drawn as an SVG overlay on the cell under the pointer in either heatmap (the calendar or the weekday by hour grid); cell fill, layout and ramp unchanged, no transition | Same as the focus ring |

**Scale rule (D-04, binding for both heatmaps).** The scale is rank-based, never linear min-max. Take the non-zero values of the current slice (hours per day for the calendar, hours per weekday-hour cell for the grid), sort them, and set the four cut points at their 20th, 40th, 60th and 80th percentiles. Level 1 is a value up to the first cut, level 5 a value above the fourth. A value of zero is level 0 and is never given a shade. If cut points coincide (many identical values), the duplicate levels collapse and the legend shows only the levels in use. The scale is computed once per chart across all years together, so a shaded day means the same amount in every year. It is recomputed when the selector changes, so a small slice still uses the whole ramp.

**Legend (both heatmaps).** One row under the chart: the word "Less", the swatches for level 0 and every level in use, the word "More", then a Caption note stating the darkest boundary (copy below). Swatches are `aria-hidden`; the note is real text.

2. New Caption variant (Label size at weight 400) — no new size, no new weight.
3. Tooltip uses the existing neutral-text token `#3c4043` as a surface, with white text.
4. Focus ring on heatmap cells is an SVG two-tone outline; same 3px `#1a73e8`.
5. Chart mark geometry exceptions listed under Spacing.

### 1. Placement and document order

```
h2  Activity_history                      (existing DashboardSection heading)
  h3  Playtime

    Totals               (3 tiles)
    Split table          (All + per value)           only when a split column exists
    Excluded-row notice                              only when > 0
    h4  Hours per day            → year blocks (h5 per year), legend
    h4  Hours by weekday and time of day → grid, timezone caption, legend
    h4  Session length           → 12-row list, caption
  h3  Login history                                  placeholder, see below
    Body note  SECTION_NOTE_PENDING ("Dashboard coming in a later update")
[existing import caption from DashboardSection]
```

- **Login history placeholder.** Phase 3 D-02 fixes both sub-headings inside Activity_history. Phase 4 renders the second `h3` with the existing pending note so the section does not silently drop the promise; Phase 6 replaces the note. **Decision**, rationale: reusing existing copy adds no new strings and keeps the section honest.
- The nav link, section id and anchor are unchanged. The Activity_history nav link keeps its Phase 3 default weight once `ready`.
- `IP` is never read, rendered, put in a tooltip, an `aria-label`, a `title`, a `data-*` attribute or the test hooks anywhere in this phase (CONTEXT integration point; Phase 6 owns IP display).

### 2. Playtime state matrix

`data-testid="playtime"` carries `data-state`.

| `data-state` | When | What renders |
|--------------|------|--------------|
| `loading` | Dataset displayed, aggregates for the current slice not yet received (return visit, or aggregates computed on demand) | The `h3`, then Body text `Calculating playtime...` in the status line; no selector, tiles or charts. `aria-busy="true"` on the block. |
| `ready` | Aggregates received, at least one usable session | Everything in section 1 |
| `updating` | `ready`, and a new slice was requested | Previous slice's tiles and charts stay on screen unchanged; the status line reads `Updating charts...`; `aria-busy="true"` on the charts container. The latest request wins; a response for an older selection is ignored. |
| `no-session-file` | Activity_history has rows but no session file at all — neither `Sessions.csv` nor a per-game `<GAME>_Game_Sessions.csv` (only `Logins.csv`) | The `h3` and Body text `This export has no session file, so there is no playtime to show.` No selector, tiles or charts. |
| `no-usable-sessions` | a session file is present but none of them holds a usable session (header only, or every row excluded) | The `h3`, Body text `No usable sessions were found in this export.`, and the excluded-row notice if the count is > 0. No selector, tiles or charts. |
| `error` | The worker query or aggregation failed | The `h3` and the destructive-chrome message (copy below). No selector, tiles or charts. No retry button: dropping the export again is the retry, and the dataset on screen is unchanged. |

> **Amended 2026-10-01 (plan 04-15)** — this amends the 2026-09-29 approval, after the real export was inspected. Both rows named `Sessions.csv`, which is the synthetic fixture's single file; a real export keeps playtime in `{WOT,WOTB,WOWS}_Game_Sessions.csv`, so "no session file" must mean neither shape, and a header-only `WOWS_Game_Sessions.csv` is present-and-empty rather than absent.

The status line is one `<p data-testid="playtime-status" role="status" aria-live="polite" aria-atomic="true">` that exists in every state and is empty when nothing is happening (an empty live region adds no height). It is the only new live region; Phase 3's notice slot keeps its own role. It also announces the selection summary after a split change (copy below).

> **Amended 2026-10-01 (plan 04-16)** — this amends the 2026-09-29 approval, after UAT gap G-04-5. One element is added to the block, and it is deliberately **not** a state: the cache-cleared notice renders directly under the status line, OUTSIDE every state branch, and never changes `data-state`. The matrix above is unchanged — the `updating` row's rule that a response for an older selection is ignored still holds, and still reconciles `requested`; what changes is that the block now also says, once, why a selection could not be applied.

### 3. Split selector (D-03)

- **Column choice. Decision**, rationale: the worker considers exactly three columns in this order: `GAME` — the game code in the session FILE's name, upper-cased, `WOT_Game_Sessions.csv` giving `WOT` — then `SERVER_NAME`, then `CLIENT_PLATFORM`. It uses the first that has **2 to 50 distinct values** among rows it can bucket (values are trimmed strings; an empty value counts as one value labelled `(not recorded)`). If none qualifies, there is no selector, no split table and no overlap note; every chart shows All, and nothing tells the user a split is missing. No other column may ever be offered (this also keeps `IP` and `CLIENT_BUILD` out). The chosen column name travels with the aggregates so the label is data-driven. `GAME` leads because the real export names the game in the file name and carries neither `SERVER_NAME` nor `CLIENT_PLATFORM` at all, so it is the only one of the three a real export can ever produce; a legacy `Sessions.csv` names no game, so its one null game is a single value that never qualifies on its own, and the rule falls through to the other two exactly as before. **One game with rows is not a split**: it is a single distinct value, so the user with a single `WOT_Game_Sessions.csv` sees exactly the all-only view and the page makes no claim about which game a lone file holds — there is deliberately no single-value state to announce.
  - **Amended 2026-10-01 (plan 04-15)** — this amends the 2026-09-29 approval, which considered exactly two columns because the real 2021 export was not available to that research and therefore could not be named. Plan 04-14 read the real export and it keeps playtime in per-game files, so the title question is answered by the file name and the decision above is now three columns deep. The two-to-50 rule, the counting of usable sessions only, and the silence when no column qualifies are all unchanged.
- **Label** is the column's true name in words: `GAME` → "Game", `SERVER_NAME` → "Server name", `CLIENT_PLATFORM` → "Client platform". Visible `<label for>` above the control, Label role. `GAME`'s label is safe to show because the code comes from the export's own file name, so the page asserts only what the file says and nothing is mapped to a friendlier title.
  - **Amended 2026-10-01 (plan 04-15)** — adds `GAME` → "Game" to the two labels the 2026-09-29 approval listed. The control may now name a game, which the earlier decision forbade, because the real export names it too.
- **Control:** native `<select data-testid="playtime-selector">`. First option "All" (default and selected on load), then each value ordered by hours descending (ties: ascending by string). Native keyboard and screen-reader behaviour is used as is; no custom listbox. Style: Label 14/600 `#3c4043`, `padding: 8px 12px`, `1px solid #80868b`, radius 6px, bg `#ffffff`, hover bg `#f1f3f4`, accent focus ring, `max-width: 100%`. A long value is truncated by the native control only; the full value is always visible, wrapped, in the split table.
- **State lifetime.** The selection is component state only (not persisted). It resets to "All" whenever the dataset id changes (replace), when the dataset is cleared, and whenever the selected value is absent from the current value list. A stale value is never displayed.
- **Effect.** Choosing a value filters every total and every chart (D-03), including the excluded-row count, the calendar scale, the weekday × hour scale and the duration bins. After the update, the status line announces the summary (see Copywriting).

### 4. Totals summary (ACTIVITY-01, D-06)

- Three tiles in a `<dl>`: Total playtime · Sessions · Active days. Layout `display: grid; grid-template-columns: repeat(auto-fit, minmax(128px, 1fr)); gap: 16px`. Tile: `#f7f7fa`, `1px solid #dadce0`, radius 6px, padding 16px, `dt` above `dd` with a 4px gap.
- Values are for the selected slice. Total playtime is the merged-overlap hours of D-02 (computed in the worker, never on the main thread). Sessions is the count of usable sessions. Active days is the count of distinct start days with at least one usable session (same day basis as D-01/D-02).
- **Hours formatting (Decision, one rule everywhere, in `ui-copy.ts` as `formatHours`):** under 1 hour show whole minutes with unit `min` (a non-zero total under one minute shows `<1` with unit `min`); 1 hour up to but not including 100 hours show one decimal with a trailing `.0` dropped (`3.5`, `42`); 100 hours or more show a rounded integer with thousands separators (`1,204`). Unit is `hour` when the numeral is exactly `1`, otherwise `hours`. All numbers use `en-US` formatting.
- **Split table** (only when a split column exists), directly under the tiles. A real `<table data-testid="playtime-split-table">` with a caption `Hours by {column name in lower case}`, header cells `{Column label}` and `Hours`, first row `All` then the values in selector order. At most 8 value rows are shown; if there are more, a final row `{n} more in the selector` fills the first column. The row for the current selection has weight 600, bg `#f1f3f4` and `aria-current="true"` (selected state is therefore also shown by weight, not by colour). Rows are not interactive; the selector is the only control. Beneath the table, one Caption note explains the consequence of D-02 (copy below).
- **Excluded-row notice (D-02).** When the slice's excluded count is > 0, render one line directly under the totals (and under the split table when present): an amber pill `{n} session row(s) excluded` (Label, same chrome as the skip tag: `1px solid #f9ab00`, bg `#fef7e0`, text `#8a5a00`, `border-radius: 999px`, `padding: 0 8px`) followed by the Caption explanation. Never rendered as "0 ... excluded". Excluded rows are those with a missing or invalid start or end time, or an end before the start; they appear in no tile, chart or table. Under "All" the count is the whole-file count; under a value it is that value's excluded rows. This count is separate from Phase 2's parse-level "rows skipped" tag (that tag stays in the section's import caption).

### 5. Calendar heatmap (ACTIVITY-02, D-04)

**Structure.** One block per year that has activity, newest year first (**Decision**, rationale: the most recent play is what most people look for first; the sticky year label keeps older years navigable). Each year block contains a sticky head and a horizontally scrollable SVG:

```
.year
  .year-head (sticky)   h5 "2019"  +  Caption "412 hours · 1,203 sessions · 201 active days"
  .scroller (overflow-x: auto)   svg 626 × 97
```

- **Sticky year label (D-04).** `.year-head` is `position: sticky; top: calc(var(--nav-offset) - 16px)` (the sticky nav's height, derived from the one token), height 32px, bg `#ffffff`, `border-bottom: 1px solid #dadce0`, `z-index: 0` (below the nav's 1). It sits **outside** the scroller, as its sibling, because a sticky element inside an `overflow` container sticks to that container instead of the page. It sticks only while its own year block is in view.
- **Collapsing empty years.** A year with no sessions in the slice has no grid and no head. A run of consecutive empty years between the first and last active year renders as one Caption line (`2011-2013: no sessions recorded`; a single year: `2012: no sessions recorded`). This bounds the node count by active years and absorbs a stray bad date (a 1970 row) without drawing forty empty grids.
- **Geometry (calendar).** Weeks run Monday to Sunday: rows are Monday (top) to Sunday (bottom); columns are weeks, 54 at most. Column index = `floor((dayOfYear0 + weekdayIndexOfJan1) / 7)`. Cell `x = 32 + col * 11`, `y = 20 + row * 11`, `10 × 10`, no rounded corners, separated by the 1px white stroke. Month labels sit in the top band at the column of each month's first day. Weekday labels "Mon", "Wed", "Fri" sit in the gutter on rows 0, 2 and 4 (`text-anchor: end`). All days of an active year are drawn (Jan 1 to Dec 31), so the node count is at most 366 cells per active year plus 12 month labels and 3 weekday labels. Days before the first or after the last recorded session inside an edge year are drawn as level 0.
- **Cell value and colour.** Cell = hours played on that start day for the slice (D-04). Colour comes from the rank scale in Color, applied as a class per level (`level-0` .. `level-5`), never as an inline style. Session count appears only in the tooltip and the accessible name.
- **Legend** under the last year block: `Less` swatches `More` and the note. One legend for the whole chart (the scale is shared across years).
- **Text, not colour.** Each year head prints the year's hours, sessions and active days. The tooltip and accessible name give the per-day exact values.

**Accessible structure.** Each year's `<svg>` has `role="grid"` and `aria-label="Playtime calendar {year}"`; each weekday is a `role="row"` group and each day a `role="gridcell"` rect with `aria-label` (copy below). A Caption hint above the first year (`Use the arrow keys to move between days.`) is linked with `aria-describedby`. All decorative elements (legend swatches, month and weekday labels are visible text and stay readable) follow: swatches `aria-hidden`.

**Keyboard (roving focus, one tab stop for the whole chart).**

| Key | Behaviour |
|-----|-----------|
| Tab | Enters the chart on one cell (initially the first cell of the newest year, then the last-focused cell) and leaves it on the next Tab; cells are never individual tab stops |
| Left / Right | Previous / next week, same weekday (7 days earlier / later); crosses into the adjacent year when it runs off the edge; stops at the first or last drawn day |
| Up / Down | Previous / next weekday inside the same week column; does not wrap into another week |
| Home / End | First / last week of the year on the current weekday row |
| PageUp / PageDown | Same calendar date one year earlier / later (clamped to the nearest drawn day; skips collapsed empty years) |
| Escape | Hides the tooltip without moving focus |

The focused cell is scrolled into view with `scroll-margin-top: calc(var(--nav-offset) + 16px)` (nav plus the 32px year head), so it never ends up under the sticky nav or the year head.

### 6. Weekday × hour heatmap (ACTIVITY-03, D-01)

- One SVG, 624 × 192: 48px weekday gutter (`Mon`..`Sun`, Monday first, matching the calendar), a 24px band with hour labels every third column (`00:00`, `03:00` .. `21:00`), then 7 rows × 24 columns of 24px cells separated by the 1px white stroke. 168 cells, fixed regardless of data size.
- **Cell value (Decision).** Hours of merged play time that overlap that weekday-hour cell, across all years, for the slice. Rationale: this is the accurate weekly rhythm (play after midnight lands in the next weekday's early hours) and the grid's cells sum to the same total as the tiles. It differs from the calendar's start-day rule only for sessions that cross midnight; see UI Considerations (unresolved row) for the planner.
- **Timezone basis (D-01, success criterion 3).** A Caption directly under the `h4`, always visible, never only in a tooltip: `Hours are as recorded in the export (likely UTC or server time), not converted to your local time.` The calendar carries a shorter Caption under its `h4`: `Dates are as recorded in the export.` No toggle, no conversion.
- Same rank colour scale (computed over the non-zero cells), same legend pattern. Role `grid`, `row`, `gridcell`, one tab stop, roving focus.

| Key | Behaviour |
|-----|-----------|
| Arrow keys | Move one cell in that direction; stop at the edges, no wrap |
| Home / End | First / last hour of the current weekday row |
| Escape | Hides the tooltip |

Initial tab stop is Monday 00:00 (predictable). No PageUp/PageDown.

### 7. Session-duration distribution (ACTIVITY-04, D-05)

- **Bins (Decision).** Fixed edges, the same for every slice, so switching the selector never re-labels the axis. Twelve bins on a roughly logarithmic 1-2-5 progression, lower edge inclusive and upper edge exclusive: `Under 1 min`, `1-2 min`, `2-5 min`, `5-10 min`, `10-20 min`, `20-30 min`, `30-60 min`, `1-2 hours`, `2-4 hours`, `4-8 hours`, `8-16 hours`, `16+ hours`. The last bin absorbs every longer session, so there is no separate outlier bucket (D-05). A zero-length session (end equals start) is usable and falls in `Under 1 min`. Bin count is 12 always, including empty bins.
- **Layout.** An `<ol aria-label="Sessions by length" data-testid="duration-chart">`, one `<li data-testid="duration-bin">` per bin, shortest first. Each row is a grid with three columns: label (96px), bar (flexible), count text (104px), `column-gap: 16px`, rows 4px apart. The bar is an `aria-hidden` SVG (`viewBox="0 0 100 12"`, `preserveAspectRatio="none"`, 12px tall, one `<rect>` at `x=0` whose `width` attribute is the count as a percentage of the largest bin). A non-empty bin is never narrower than 1 unit, so it stays visible. The bar length is linear in count (the log scale is on the duration axis, D-05). An empty bin shows no rect and the count `0`.
- **Text.** Count text is `{n} · {p}%` (percent of usable sessions in the slice; a non-zero share under 0.5% shows `<1%`). The whole row is readable as text, so there is no separate table view and no tooltip on this chart. The bin counts always sum to the Sessions tile.
- **Explanation** (Caption, under the `h4`): `Each bar covers a longer range of session lengths than the one before it, so short and long sessions are both visible.` No median or percentile text is added (CONTEXT: only if cheap and clearly useful; it is neither, so it is deferred).
- **Not interactive.** The bars are not focusable; the list is read in document order.
- **Narrow width (below 480px).** Each row becomes two lines: label and count on the first line (`grid-template-columns: 1fr auto`), the bar on its own full-width line beneath, so the bar does not shrink to a few pixels. This is a layout-must-not-break requirement, not touch polish.

### 8. Tooltip (both heatmaps)

- One shared element for the page: `<div data-testid="chart-tooltip" aria-hidden="true" hidden>`. It is `aria-hidden` because every cell already carries the same text as its accessible name.
- Opens on pointer hover over a cell (one delegated `pointerover` listener per chart, never one listener per node) and on keyboard focus of a cell. It follows the latest of the two. It closes on pointer leave, on blur, on Escape, and on scroll or resize.
- Chrome: `#3c4043` bg, `#ffffff` text, radius 6px, padding `8px 12px`, `max-width: 240px`, `pointer-events: none`, no shadow, no arrow, no transition and no delay. Two lines with a 4px gap.
- Position: `position: fixed` (so no `overflow` container clips it), centred over the cell with an 8px gap, flipped below the cell when there is not `var(--nav-offset) + 8px` of room above, clamped to keep 8px from each viewport edge. Set from script via the element's CSSOM (`el.style.left` and `el.style.top`); never a `style` attribute or a Svelte `style:` directive, because the build-time CSP has no `style-src 'unsafe-inline'` and `svelte/no-inline-styles` is an error in this repo. Cell fills are classes, SVG geometry is attributes.
- Content: calendar cell, line 1 `Sun, Mar 3, 2019`, line 2 `3.5 hours · 4 sessions` (or `No sessions`). Weekday × hour cell, line 1 `Tuesday, 21:00-22:00`, line 2 `42 hours played` (or `No sessions`). Dates are formatted from the recorded year, month and day parts and never through the viewer's timezone (same rule as Phase 3 D-15). The tooltip never contains an IP.
- WCAG 1.4.13: dismissible (Escape), hoverable content is not required because the tooltip is non-interactive and disappears with the pointer, and it persists while the cell keeps focus.

### 9. Motion

None. No animation, no transitions on cells, bars or the tooltip, no animated re-layout when the selector changes (D-29 continues). The existing reduced-motion handling for the spinner and smooth scrolling is untouched. Focus-driven scrolling uses the browser default.

### 10. Accessibility (summary)

- Every state is stated in visible text; colour only reinforces. The tile numbers, the year-head summaries, the split table, the duration rows, the legend note and every tooltip's text give the exact values. The ramp's low steps are below 3:1 and are covered by that text (relief rule).

- One new live region (`playtime-status`, polite, atomic). Selection announcements go there and nowhere else. - One tab stop per heatmap plus the native `<select>`; the duration list is read in order. Tab order follows document order.
- Selector values are untrusted text: plain interpolation, no `{@html}`, wrapped in the table.
- Privacy: no IP, no account email, no birth data in any string, attribute, tooltip or test id of this phase.

  svg drew — and not a pixel literal, so the check follows the runner's face
  rather than this machine's.

### A-2 — 2026-10-02, plan 04-17, UAT gap G-04-UI-3 (sticky-head clause): the year head's height and the focus correction

These are recorded as **observations, not constants**. The year head declares a
32px `min-height` on a content-box element with 4px of vertical padding and a
1px rule, so its used height is 41px with the summary on one line (1280px) and
52px with the summary wrapped (375px) in the synthetic export measured on
2026-10-02 — and it grows again if the summary wraps to a third line. The
"32px tall" above is the declared minimum and was never the used height. The
head's height is therefore not changed: making a phone head a single line is not
possible without truncating the per-year summary, which is the non-colour relief
for the ramp.

So nothing may assume 32. The sticky `top` is the nav offset alone
(`calc(var(--nav-offset) - 16px)`), and the focus correction reads the focused
cell's own year head's `offsetHeight` after focus settles, and clears the nav,
that measured height and the 8px gap.

Two statements above are superseded by this entry:

- The section 5 claim that the focused cell is scrolled into view with
  `scroll-margin-top` is superseded: `scroll-margin-top` is not honoured on an
  SVG `<rect>`, so the correction is a **measured instant scroll** instead.
- The direction is stated here because it was inverted in the build until
  04-17. A focused cell above the clear line moves **down on screen** by the
  page scrolling **up**, so the scroll is negative. The weekday-by-hour grid
  uses the same helper with a head height of 0, so a cell there is cleared of the
  nav by 8px. `focusScrollDelta` returns the scroll to apply with its own sign
  and the caller passes it through unchanged.

### A-3 — 2026-10-02, plan 04-18, UAT gap G-04-UI-2: the summary tile's value at narrow widths

A tile's value is a FORMATTED NUMBER and a fixed word. It is not the child the
Spacing section describes, so that section's sentence — every flex or grid child
that can hold untrusted text sets `min-width: 0` and `overflow-wrap: anywhere` —
is read as applying to children that hold untrusted text, which a tile value does
not. The anywhere value was applied here by that blanket reading, and it is what
broke the figure.

Measured in Chromium against the BUILT app with the synthetic 5,000-session
export on 2026-10-02, all three tiles in a two-per-row 375px card: a tile's
inner width is 104.5px, a four-digit hours numeral set in the Display role
measures 76.5px, and its unit set in Label measures 38.4px — 118.9px of the
104.5px they share, once the 4px gap between them is counted. A flex item's
minimum width under `overflow-wrap: anywhere` is one character, so both parts
shrank instead of either wrapping: the numeral rendered across two lines and the
unit as "hour" over "s", in a dd 67.2px tall inside a 124.8px tile. At 1280px the
same pair measured 76.5px and 38.4px on one line, and does still.

The amended rule:

- A tile's value is a wrapping flex row of two parts that are never broken: the
  numeral, and the unit.
- Those two share a baseline on one line when they fit, and the unit takes its
  own line UNDER the numeral when they do not. The phone case is the second one,
  and it is the reading the summary needs at 375px. The unit itself never breaks
  either, so "hours" is never read as "hour" over "s".
- `overflow-wrap: anywhere` remains for the untrusted text in this component —
  the split table's values and the explanatory notes — and does not apply to the
  three tile values.
- The accepted limit: a numeral wider than a tile's inner width (seven digits
  with separators, over a million sessions) overflows its padding rather than
  breaking. A number split across lines is a wrong reading of a figure, not a
  degraded one, and the scale target is 60,000 sessions.
- Unchanged by this amendment: the 128px tile minimum, two tiles per row at
  375px and three at the card's full width, the 16px tile padding and gap, and
  the Display numeral / Label unit role assignment. Raising the tile minimum to
  force one tile per row was considered and declined; stacking the unit keeps the
  two-per-row contract and does not lengthen the summary by a tile row.

### A-4 — 2026-10-02, plan 04-18, UAT gap G-04-UI-3 (legend clause): the legend note

The Legend (both heatmaps) paragraph in Color says the note follows the swatches.
It is amended: the note is ALWAYS its own line, spanning the width of the legend,
with 8px — the Spacing scale's `sm` step — between the Less / swatches / More row
and the note. The 4px gap between the words and the swatches is kept.

Measured in Chromium against the built app with the same synthetic export on
2026-10-02, before the amendment: the weekday-by-hour legend's shorter note
followed More on the same line at 1280px, 166.56px indented under the swatch row;
the calendar's longer note sat on its own line only because it did not fit beside
More. Each had 4px between itself and the row above it, at both widths.

- The legend row's gap is the 8px `sm` step between the ROWS, with the existing
  4px column gap unchanged, so Less, the swatches and More stay 4px apart.
- The note takes a full-width flex basis, so its placement is a rule rather than a
  consequence of the sentence's length. That is the difference the audit saw
  between the two legends, and the amendment removes it.
- The note keeps its `min-width: 0` and `overflow-wrap: anywhere`: it embeds a
  formatted hours value and can be long.
- No DOM node, attribute or class was added or removed, so the node counts the
  scale spec compares between the 5,000- and 60,000-session presets are
  unchanged.
- This entry covers the shared `ChartLegend` the two Playtime heatmaps import. The
  Phase 5 flow legend is a separate copy of the same chrome and is not governed
  by this amendment.
