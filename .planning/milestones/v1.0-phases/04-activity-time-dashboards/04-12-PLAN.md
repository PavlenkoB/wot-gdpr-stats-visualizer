## Planner assumptions and flags

- **Chromium.** It cannot be downloaded in the cloud sandbox, so every browser assertion is verified by `playwright test --list` here and by a CI or developer run. The human-check blocks name that run. Unit tests do run here.
- **Additive test file.** 04-VALIDATION.md names `tests/unit/playtime.test.ts` for the scale unit row. This plan puts the scale unit tests in `tests/unit/playtime-scale.test.ts` and the worker-level scale test beside the other worker tests, keeping `playtime.test.ts` (owned by plans 04-03 and 04-06) unchanged. The VALIDATION.md map should gain these rows.
- **Fixture cost.** Building the 60,000-session export in memory takes seconds; every browser and unit test builds it lazily inside the test, so `--list` and unrelated tests never pay for it.
- **fake-indexeddb write time.** The worker-level test writes 60,000 or more rows into fake-indexeddb. Measured while planning: 72,000 header-keyed rows through chunked bulkPut took about 3.6 s in this sandbox (a 50,000-row read took 338 ms), so CSV parse and aggregation dominate. The ingest runs once in a beforeAll with a 180,000 ms timeout and the SUMMARY records the measured duration; a timeout is a real finding to report, not something to hide by shrinking the fixture, because the criterion needs 50k or more sessions.
- **Node-count constants.** `NODE_COUNT_SLACK` (24) allows the two legends to differ by up to five level swatches each when the rank scale collapses duplicate levels differently for the two sizes; `CHART_OVERHEAD_NODES` (800) is the estimated fixed cost of year heads, row groups, month and weekday labels, the hour grid, the duration list, the legends and the tooltip for twelve years. If the measured overhead differs, the executor records the measured value in the SUMMARY and sets the constant to the measured value plus 100, provided the 60,000-session total stays under the calendar cell count plus 1,500 (still one node per 40 sessions).
- **Residual risk carried from plan 04-05.** The scale fixtures have twelve active years. An export with a stray record decades away from the rest (many mostly empty years) is the accepted T-04-08 risk and is not covered here.
- **Real-export check.** The column rule and the timestamp shape (A1, A2 in the research) came from a small real sample; Task 3 records a human check against a real export. Real exports never enter the repository or CI (tests/fixtures/README.md policy).
