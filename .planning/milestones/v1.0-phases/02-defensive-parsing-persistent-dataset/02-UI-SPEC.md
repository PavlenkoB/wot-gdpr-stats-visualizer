## Spacing Scale

Declared values (must be multiples of 4) — reusing the scale already established in Phase 1's CSS (`src/app.css`, `Dropzone.svelte`, `ResultsView.svelte`, `CategoryBadge.svelte`, `FailureBanner.svelte`), not reinvented:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-free inline gaps (badge internal gap) |
| sm | 8px | Compact element spacing (badge-list gap, button padding-y, skip-count-tag internal gap) |
| md | 16px | Default element spacing (results-view gap, banner margins/padding-x, confirm-panel internal gap, persistent clear-data bar padding) |
| lg | 24px | Section padding (`main` top/bottom padding, established) |
| xl | 32px | Layout gaps — not used by Phase 1; available if a Phase 2 element needs a larger break (none currently does) |
| 2xl | 48px | Major section breaks — not used in this phase |
| 3xl | 64px | Page-level spacing — not used in this phase |

**Exceptions (pre-existing, continued — do not introduce new ones beyond these):**
- `12px` — `Dropzone.svelte` `.processing-status` gap and `FailureBanner.svelte` padding-y. Phase 2 reuses this exact value for the new duplicate-loaded banner and the confirm-panel's own padding-y, for visual consistency with `FailureBanner`.
- `20px` — `main` and `.dropzone` padding. Unchanged; no new Phase 2 element introduces this value independently.

## Typography

Reusing sizes already established in Phase 1's CSS. Phase 2's **new** elements (confirm panel, persistent clear-data control, duplicate banner, skip-count tag, import timestamp, cache-check loading state) must draw from exactly these four declared roles — do not introduce a fifth size.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.4 |
| Heading | 18px | 600 (semibold) | 1.3 |
| Display | 28px | 600 (semibold) | 1.2 |

- **Body (16/400/1.5):** confirm-panel message text, duplicate-loaded banner text, cache-check loading status text, `FailureBanner` text (existing) — matches the `:root` default already set in `src/app.css`.
- **Label (14/600/1.4):** category badge name/count text (existing `.badge-name`), the new row-count/skip-count text appended to badges (D-05), the new skip-count tag (D-04), the new "Imported on ..." timestamp (D-10), button labels ("Start over", "Clear my cached data", the confirm panel's dismiss button — "Keep current data" / "Keep cached data" — and its destructive commit button).
- **Heading (18/600/1.3):** the account heading (existing `.account-heading`) — unchanged, no new heading-level text introduced by Phase 2.
- **Display (28/600/1.2):** the page `<h1>` (existing, global `src/app.css`) — inherited only, not used by any new Phase 2 element.

**Pre-existing sizes NOT part of Phase 2's declared scale — do not propagate to new components:** 15px (`.summary`, existing `.start-over` button) and 20px (global `h2`). These remain in the codebase from Phase 1 but should not be reused for anything new this phase; new label-level text uses 14px per the table above.

**Weights:** exactly two — 400 (regular, body copy) and 600 (semibold, labels/headings/buttons). The existing `.start-over` button currently uses `font-weight: 500` — a pre-existing Phase 1 outlier. Do not replicate 500 in any new Phase 2 element; new buttons (persistent clear-data control, confirm-panel buttons) use 600.

## Color

Reusing the palette already established in Phase 1 (`Dropzone.svelte`, `CategoryBadge.svelte`, `FailureBanner.svelte`, `ResultsView.svelte`) — no new hues introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` | Page background (`:root` background, unchanged) |
| Secondary (30%) | `#f7f7fa` / `#f1f3f4` | Neutral surfaces: dropzone idle background (existing), unknown-status badge background (existing), the new persistent clear-data bar background, the new confirm-panel's dismiss-button surface ("Keep current data" / "Keep cached data") |
| Accent (10%) | `#1a73e8` | Reserved for: the dropzone's drag-highlight border/background (existing), `:focus-visible` outlines app-wide (existing), the processing spinner's active arc (existing). **Not used for any Phase 2 destructive or confirm affordance** — see Destructive/Caution below. |
| Destructive | border `#c5221f` / background `#fce8e6` / text `#8a1c17` | Reserved for: `FailureBanner` (existing, unchanged), and the shared `ConfirmPanel`'s destructive commit button (the actual point of irreversible commitment across all three destructive flows: replace-on-drop, Start Over, Clear my cached data) |

Accent reserved for: dropzone drag-highlight, `:focus-visible` outline ring (all interactive elements), processing spinner. Never used on a destructive trigger, a destructive confirm button, or a status/informational banner.

**Additional pre-existing semantic (status) colors, reused by this phase — not new hues, documented here because Phase 2 extends their usage beyond `CategoryBadge`:**

| Semantic | Value | Existing usage | New Phase 2 usage |
|----------|-------|-----------------|--------------------|
| Success/green | border `#34a853` / bg `#e6f4ea` / text `#0d652d` | `supported`-status badge | none new this phase |
| Caution/amber | border `#f9ab00` / bg `#fef7e0` / text `#8a5a00` | `known-deferred`-status badge | the shared `ConfirmPanel`'s container chrome (border/background — the panel's own text stays default body color for readability); the per-category skip-count tag (D-04) |
| Neutral-info/grey | border `#80868b` / bg `#f1f3f4` / text `#3c4043` | `unknown`-status badge, `.summary` text color | the duplicate-already-loaded banner (D-12); the new "Imported on [date]" timestamp text |

**Destructive-trigger design rule (Claude's discretion, not specified in CONTEXT.md):** trigger buttons ("Start over", "Clear my cached data") are styled **neutral** (grey outline, matching the Secondary/neutral-info palette), not red — clicking them does not yet destroy anything. Red is reserved exclusively for the `ConfirmPanel`'s commit button, the actual point of no return. This also means the existing `.start-over` button's blue accent styling from Phase 1 must be restyled to neutral grey in this phase, since Start Over is now destructive (D-15) and accent blue is reserved for the primary, non-destructive import action only.

## UI Considerations

Applicable state considerations resolved: 9 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Dropzone (no cached dataset) | ✅ covered | Unchanged Phase 1 dropzone; no heading, prompt copy per Copywriting Contract |
| empty → post-clear | Dropzone shown after "Clear my cached data" / "Start over" confirm | ✅ covered | D-20 acknowledgment banner ("Cached data cleared") renders above/alongside the dropzone before it settles to the plain empty state |
| loading | Cache-check on page init (D-07/D-08) | ✅ covered | Standalone centered spinner + "Checking for a saved export..." status text, reusing the existing `Dropzone.svelte` spinner CSS pattern, shown before either ResultsView or Dropzone is decided |
| loading | Import in progress, per-category (D-11) | ✅ covered | Existing dropzone `.processing-status`/spinner pattern, extended with per-category progress text |
| error | Worker/parse/Dexie/quota failure | ✅ covered | Single unchanged `FailureBanner`, per established single-error-path pattern (see Copywriting Contract note) |
| populated | ResultsView with row counts, skip counts, timestamp | ✅ covered | Badge text extended per D-05; skip-count tag conditionally rendered; timestamp shown via Neutral-info label styling |
| zero-one-many | A category with 0 rows parsed, or 0 rows skipped | ✅ covered | Badge always shows the row count including "0 rows" (never blank/omitted); the skip-count tag is conditionally rendered ONLY when `skippedRowCount > 0` — never shows "0 rows skipped" |
| overflow | Many badges + skip-count tags wrapping on narrow viewports | ✅ covered | Reuses the existing `.badge-list` `flex-wrap` container (Phase 1); skip-count tags sit inside the same wrapping flow, not a fixed-width sidebar |
| duplicate-drop (informational, not empty/error/populated) | Re-drop of identical hash-matched zip (D-12) | ✅ covered | Distinct Neutral-info banner, shown before any unzip/parse work starts, then results view shown/stays shown |
| confirm-pending overlay | Replace-on-drop, Start Over, Clear my cached data (D-13/D-16/D-17/D-22) | ✅ covered | Shared `ConfirmPanel` component, Caution/amber chrome, neutral dismiss button ("Keep current data" / "Keep cached data") + destructive commit (red) button |
| long-text | Untrusted, unbounded category/folder names in badges | 🧪 backstop | Inherited from Phase 1 (plain-text, no truncation) — Phase 2 does not introduce new long-text surfaces, but the extended badge string (name + file count + row count) is longer than Phase 1's and has not been visually verified against a very long real category name at narrow viewport; needs a visual check during execution, not just a unit test |
| scale | Progress text and row/skip counts at the 10x-scale synthetic fixture (SC1) | 🧪 backstop | Large numbers (e.g. "Parsing Player_statistics (37/812)...", "12,345 rows skipped") must still fit on one line without wrapping mid-word at phone width — not testable by a unit assertion alone, needs a visual check against the 10x fixture during execution |
