<objective>
Close G-07-5 (UAT test 5, major): when the page scrolls, a table's sticky header paints over the sticky section nav, so the nav links are covered and a tap meant for a nav link lands on a table sort button. Plan 07-07 closed the other Phase 7 gap (GAP-WR01); this one is separate and touches different files.

Root cause, verified at planning time on a built app (GEO_FIXTURE build, 375x700, sample export, probing with elementsFromPoint, then re-probing with `isolation: isolate` applied to every `.scroller` through the CSSOM):

- LoginTable and VehicleTable: `.scroller` is `position: relative` with no z-index, so it creates no stacking context. Its header cells (`th`, z-index 2), its corner cell (`th.sticky-first`, z-index 3) and its first-column body cells (`td.sticky-first`, z-index 1) therefore join the page's root stacking context beside the nav (`position: sticky`, z-index 1). The header cells outrank the nav on value. The first-column body cells TIE the nav's value and, being later in tree order, paint over it. The UAT named only the header; the first-column body cells are a second overlap, found by measurement. Before the change the topmost element at the nav's centre was `button[login-sort-ip]` inside `th.w-ip.sticky-first` (header position) and `span.ip` inside `td.w-ip.sticky-first` (first-column position), and the vehicle table gave `button[vehicle-sort-vehicle]` and `span.id`. With the isolation applied the topmost element was a nav link in all four probes.
- CityList and CountryList: the diagnosis in 07-UAT.md says the same pattern applies. It does not. Their `.scroller` is unpositioned and their `th` is `position: sticky` with NO z-index, so they paint below the nav's z-index 1. Measured: the nav was topmost over the country list both before and after the change. The `isolation: isolate` on those two rules is applied because the gap's fix list names all four and keeps the four table scrollers one pattern; it is prophylactic and cannot go red, and the plan says so rather than claiming a failing test it does not have.

Purpose: stop any table's sticky cells from outranking the sticky nav, with the tables' own sticky header and first column untouched (Phase 7 D-01) and the nav untouched (Phase 7 D-03).
