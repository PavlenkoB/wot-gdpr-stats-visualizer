<objective>
Turn D-03 and the D-05 shape rule into failing tests before a single pane is migrated, with a shrinking allowlist (D-14) so the suite stays green while the work lands.

The guards are the real product of this phase: the CSS rewrite is mechanical once a test can read nested, token-based source and refuse everything else. Research verified three breakages that regex tweaks cannot fix (a `[^}]*` body stops at the first nested brace; `var(--fs-*)` is reported as an offender; two unit tests pass vacuously on empty matches), so the offender logic lives in one pure, tested helper built on the scanner of plan 14-01.

Purpose: plans 14-05 to 14-20 each end with "remove these files from PENDING_FILES and the guards pass"; that gate is only worth anything if it already exists and already bites. Plan 14-04 adds the nesting compile probe and retires the old per-folder font-size exemption and the three regex readers of the older guards.
Output: `tests/helpers/token-guards.ts`, `tests/helpers/migration.ts` and `tests/unit/guards/design-tokens-guards.test.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CSS text to the network | a remote url() or @import in any stylesheet would load an outside resource, outside the TypeScript fetch scan |
| markup to the CSP | an inline style attribute is blocked by the shipped CSP (no style-src) and signals a CSP-bypass pattern |
| guard to the tree | a guard that matches nothing, or an allowlist that never shrinks, stops enforcing without anyone noticing |
