Output: two optional slice fields, their computation, `PLAYTIME_VERSION` 4, and tests.
</objective>

1. `src/lib/core/types/worker-messages.ts`: add to PlaytimeSlice two OPTIONAL fields with doc comments. `longestSeconds?: number` - the longest single usable session in the slice, end minus start in seconds, RAW (overlapping sessions are not merged for this figure: it answers "one login to logout"); 0 when the slice has no usable session. `longestStart?: number` - the wall-clock start of that session in seconds since the epoch (so floor(longestStart / 86400) is its day number); the earliest start wins a tie; 0 when the slice has no usable session. Set `longestSeconds` and `longestStart` on the returned slice; an empty `usable` list yields 0 and 0. Do not change any other field, any ordering or any existing comment's claim; add one paragraph to the function's doc comment saying why the raw length is used (the merged increment would credit a fully overlapped session zero). Because rankAggregates and buildGameScopes both build every slice through aggregateSlice, the all-games slice, every split value's slice and every per-game scope get the fields with no other edit.
