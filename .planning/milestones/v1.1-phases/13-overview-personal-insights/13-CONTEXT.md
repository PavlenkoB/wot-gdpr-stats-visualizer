# Phase 13: Overview personal insights - Context

**Gathered:** 2026-10-23
**Status:** Ready for planning

<domain>
## Phase Boundary

The Overview becomes a personal-insights page: a grouped bento of tiles (Pinned, Time, Tanks, Records, Totals) computed on the user's device from the loaded dataset. Every tile shows one number and the rule behind it. Tiles can be pinned and expand in place. World of Tanks insights first; the structure is a per-game definition list so WoWS and Blitz can add theirs later.

In scope: the insight model and worker channel, the bento UI (sketch 030 and the Overview canvas), the build-time tank table and its refresh script, pin persistence, absent-data rows, tests including zero-network and PII assertions.

Out of scope: insights for games other than WoT (only a per-game logged-in time strip), new data categories, changes to existing panes, a phone two-up toggle, dark mode, any new network request.

</domain>

<decisions>
## Implementation Decisions

### Data path
- **D-01:** Insights are computed in the worker through ONE new `overview` channel in `src/lib/worker/data-queries.ts`, answered from the same Dexie snapshot as the other channels, memoised per import. This deliberately drops the old "Overview issues no worker query" rule (it existed so the Overview could not supersede an open pane's query; a dedicated channel cannot). — **Reversibility:** costly — the channel validator, client, memo and tests all depend on it.
- **D-02:** The Overview renders the grid immediately with skeleton tiles and fills them when the single channel answer arrives (no per-tile flicker). One error banner reuses the existing failure copy pattern. Returning to the Overview is instant from the memo.
- **D-03:** The old status chips and one-card-per-section summary are replaced by the bento. Each tile's expanded view carries an "Open <section>" link into the existing detail pane (spike requirement). Sections absent from the export appear in one dashed "Not in this export: ... needs ..." row per group, never as zeros.

### Scope across accounts and games
- **D-04:** Lifetime tiles (battles, damage, kills, XP, records, per-vehicle figures) SUM across the account folders of the loaded dataset, consistent with Phase 10 D-20. A new upload replaces the whole dataset (single active dataset), so two exports of the same player are never added together; this amends the spike rule "never sum across two exports", which cannot occur. No overlap warning is built.
- **D-05:** "Logged in" time is the union of session intervals across all accounts and games of the dataset (spike 002 definition, Phase 10 D-06 merge reused, not reimplemented). "In battle" is a separate labelled figure from BATTLE_LIFE_TIME; never labelled "in game".
- **D-06:** Insight tiles (Tanks, Records, Totals, habits) are WoT-only now but declared as a per-game definition list so another game adds its own list without touching the grid. A "Wargaming life" strip shows logged-in time per game for every game present. The Phase 10 shared game filter does NOT change the Overview.

### Tank names, class and tier
- **D-07:** The table (tank_id, nation:tag, short name, type, tier; ~19 KB gzip) is generated by a script (`pnpm run vehicles:table`) from the official WG API with the maintainer's key from `.env.local`, and the generated file is COMMITTED. The key is never shipped and CI never calls the API. Reading the Wargaming Terms of Use is a BLOCKING checkpoint before the generated file is committed. — **Reversibility:** one-way — once committed to the public repository the data cannot be withdrawn without a history rewrite and a fresh repository.
- **D-08:** At runtime the table is inlined in the worker chunk (like the geo country table): no fetch, no zero-network exception. Lookups use BOTH keys: `nation:tag` for vehicle statistics and numeric `tank_id` for record tanks. Refresh is a manual script run when tanks are added.
- **D-09:** A tank missing from the table falls back to the tag-derived name and "class unknown"; nothing is guessed. The Overview states class coverage ("class known for N% of battles"). A record whose tank id is absent says "vehicle not recorded".

### Design decisions
- **D-10:** Phone layout is a single column below 480px (container breakpoints 880 / 480, 4 / 2 / 1 columns). The optional two-up toggle from sketch 030 is dropped.
- **D-11:** Default pinned tiles: "Logged in" and "Most-played tank". A pinned tile with no data waits in its group (sketch "almost empty"); "Logged in" always shows.
- **D-12:** The fifth group is named "Totals".
- **D-13:** Value charts (including the class split) use the green-to-amber heat scale from sketch 030 with the peak labelled in text and a legend in the group heading, not the teal ramp.
- **D-14:** Pins are remembered in `localStorage` as a small list of tile ids under one key, read and written in try/catch with defaults as the fallback. They survive replacing the dataset, hold no data values, and need no Dexie schema change.

### Carried from the spikes and sketches (locked earlier, restated for the planner)
- **D-15:** Tile sizes hero 2x2, feature 2x1, metric 1x1; ONLY feature tiles widen to fill leftover cells, heroes and metrics never stretch; unfillable holes are accepted; "Signature hour" follows the hero in the Time group.
- **D-16:** Expand is "down in its own column" with no layout jump (View Transitions API, CSSOM-set names, scroll anchoring, 600 ms fallback, caught promises, synchronous intent state). Colour is only group dots and amber pinned stars; lifted shadows with hairline borders kept.
- **D-17:** Every headline figure shows its rule inline; playful labels always show the evidence; small-sample guard (100 battles per tank, 30 for plain rates); no WN8, marks of excellence or mastery; no mode-mix percentages (battle-type table covers about 5% of battles); Hall of Fame means records, not medals (ACHIEVEMENTS is empty).
- **D-18:** Order amounts, chat text and clan names are count-only or hidden by default (PRIV-01 and PRIV-02 bind this phase). Zero-network Playwright assertions cover the new Overview, and a planted synthetic sensitive value never appears in clear text.

### Amendments after research (2026-10-23, confirmed by the user)
- **D-19:** Records (most damage, XP, kills, series) take the MAXIMUM across accounts, with the record tank taken from the account that holds the maximum. Counts and totals still sum (refines D-04).
- **D-20:** "Logged in" counts every game's sessions ("across all games", copy must say so, not "WoT"). Habit tiles (longest streak, busiest day, signature hour, longest session) use WoT sessions only. The per-game strip still shows each game (refines D-05, D-06).
- **D-21:** "Credits earned" matches the Finance pane definition (deposits plus income), so the two never disagree.
- **D-22:** The lightest heat-scale step is darkened to reach 3:1 against white; the peak stays labelled in text (refines D-13).
- **D-23:** The Wargaming Terms of Use check (D-07) is a human-verify task BEFORE the task that commits the generated table; the agreement restricts derivative works and asks for a copyright line and a link in the application, so the plan must also cover that attribution.

### Claude's Discretion
- Exact tile list per group and the copy of each rule, within the insight catalog (spike 003) and sketch 030.
- Where the pure insight model lives (worker module vs feature folder) and how its tests are structured, following the existing `*-aggregate.ts` / `*-model.ts` / `*-state.ts` split.
- Accessibility details beyond the sketch (live-region wording, roving tabindex, forced-colors) within the findings.
- e2e budget: the three CI limits move together if new specs push past the ceiling (see the Phase 9 note in ROADMAP.md).

</decisions>

- `package.json` scripts gain `vehicles:table`; the generator lives beside `scripts/geo/`.

<specifics>
## Specific Ideas

- The page should read like "your story": time in game as a headline ("131 days", rule inline), most-played tank with its share, records, habits (signature hour, streak, busiest day), totals.
- Sketch 030 and the Overview canvas are the visual contract: group dots, amber pinned star, lifted shadows, heat-scale bars with the peak labelled, "Not in this export" rows.
- Tiles show real figures only from the loaded data; the repository's sketches and tests use synthetic figures (see the leak guard).

</specifics>
