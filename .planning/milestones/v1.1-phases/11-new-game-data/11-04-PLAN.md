<objective>
Make the three states of a new-game file observable and published, and clean up the rows older caches already hold: record presence facts for family files with stored and parsed counts, derive the per-pane facts the list will read from them, and narrow previously stored rows in place.

Purpose: D-09 needs the pane to say a file was skipped, which the rows table alone cannot (a skipped file leaves no row). The UI-SPEC assumption A3 needs the list to learn pane presence and counts from `ClassifyResult` without issuing a worker query. D-14 needs existing caches to stop holding non-allowlisted columns (WOWP account rows at rest today carry a nickname). The facts and the narrowing logic do not depend on any header name, but their tests read the complete spec table and the full file-name family that plan 11-03 writes (the narrowing test iterates every spec file, and the pane-facts worker case needs real pane specs), so this plan depends on 11-03 and runs in the wave after it.

Output: the `new-data-shared.ts` contract (pane ids and file keys), `newDataPaneFacts`, `parsedRowCount` on presence facts, `narrowStoredNewDataRows`, `ClassifyResult.newDataPanes` on all three payloads, and their tests.
</objective>
