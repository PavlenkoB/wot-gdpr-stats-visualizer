## Planner choices (so the executor does not "correct" them)

1. **Caption placement.** Inside the provenance block, first child, as UI-SPEC Surface 2 says. The block is a wrapping flex row, so the caption takes the full line (`flex-basis: 100%`) and the source line and import counts follow on the next line. A pane whose status shows no provenance block (muted or loading) shows no caption, because there is no combined data on screen.
2. **Account section.** `sectionProps` passes an account count of one for the `user-info` section, so the Account pane never carries the caption (it is the list of accounts).
3. **Audit result recorded in the plan.** Keyed each blocks that key by a value repeated across accounts: `VehicleTable.svelte` (the row id) and `BattleTypeSummary.svelte` (the battle-type code). All others are unique by construction: fixed id lists (`SpendSummary` figure hooks, `PlayerStats` titles, `DeviceInfo` sources, charts), values de-duplicated by a Map or Set (`PremiumBlock` unrecognised values, `PlayerStats` battle-type codes), aggregates per country or place (`CountryList`, `WorldMap`, `CityList`) and positions. The test pins this list.
4. **Why a source guard plus a data test.** Vitest has no Svelte plugin and a production build may not throw on a duplicate key, so a render check cannot catch the regression reliably. The guard asserts the key expression; the data test proves the repeated values exist in the merged view, so the guard is not vacuous; the browser spec proves the pane opens.
5. **Real-shape dates.** The expected earliest-created date in the browser spec is the fixture's hand-written EU creation date, not a value computed by the code under test.
6. **No new listed e2e test.** The suite lists 256 tests against the ceiling of 258 (measured today, D-23; the figure of 252 in the research is stale and plan 09-06 reconciles it), and plan 09-04 already created this phase's first test. This plan therefore appends steps to that same test instead of adding one, so the pane, caption, Overview and replace checks run in the same browser session as the header checks.
