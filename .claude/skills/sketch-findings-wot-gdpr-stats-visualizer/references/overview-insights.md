# Overview: personal insights (final direction)

Decided 2026-10-22 across sketches 022-030 and spikes 001-003 (`.planning/sketches/MANIFEST.md`, `.planning/spikes/MANIFEST.md`). **This replaces the Overview card grid and status chips described in `layout-and-navigation.md`.** The shell (two panes, list rows, phone list/detail screens) and the Day 10 palette are unchanged.

Reference: `sources/overview-final/030-overview-final/index.html` (behaviour), `sources/design-canvas-overview/` (hi-fi look, placeholder numbers), live canvas https://claude.ai/artifact/BJc6oZ2QEQkphxoKkq1Pa1.

## What it is
A "your story" page for the loaded export, computed on the device: grouped **tiles** (not section cards), each one number plus the rule that produced it. WoT first; the header has a game switcher so WoWS / Blitz can reuse the same tile set later (their session totals already exist: Blitz 1.9 d, Warships 0.4 d in the sample).

## Layout
- Groups in order: **Pinned**, **Time**, **Tanks**, **Records**, **Totals** (credits, battles, orders; it was called Money, but Battles and Orders are not money). Heading = small dot + caps label + hairline.
- **Three tile sizes only**: hero (2 cols x 2 rows), feature (2 x 1), metric (1 x 1). 12 px gap; hero first in the DOM so it leads on phone (order by importance, not desktop position).
- **Columns follow the DETAIL PANE, not the frame or the viewport** (`container-type: inline-size` on `.detail`, `@container` rules; the measured width is the pane's content box, i.e. the grid width): **>= 880 px: 4 columns; 480-879 px: 2 columns; < 480 px: 1 column.** Hero spans 2 cols x 2 rows and feature 2 cols in the 4- and 2-col layouts; in 1 column every span and row-span resets to auto. Verified at 1040 / 880 / 879 / 600 / 480 / 479 / 340 px: 4/4/2/2/2/1/1 columns. Shell note: in the sketch the pane is the frame minus the 240 px list and 48 px padding (frame 1170 -> pane 880; the Tablet preset, frame 768, gives a 478 px pane = 1 column). Minimum metric tile at 4 columns is 211 px: labels wrap to 2 lines at most (never 3).
- **Top-5 rows in the hero** use `grid-template-columns: minmax(72px,1fr) clamp(60px,30%,150px) auto` (name flexes and wraps, bar 60-150 px, count sizes to its text) so neither the name nor the bar collapses at any pane width.
- **Fill rule: only FEATURE tiles widen (decided 2026-10-22).** Heroes stay 2x2 and metrics stay 1x1, so a single metric never stretches across a row. `fillSpans(tiles)` is a pure function (`_shared/model.js`, no DOM, exported for node via `module.exports`, so it can be unit-tested). It takes the ordered visible tiles of ONE group (hero 4 cells, feature 2, metric 1) and returns `{ c4, r4, c2 }`: per-tile EXTRA column span for the 4-col layout, EXTRA row span (always 0 now) and EXTRA column span for the 2-col layout. It simulates `grid-auto-flow: dense`, tries every width 2..columns for each feature tile, rejects widths that would make dense placement show a tile before an earlier one (visual order must equal DOM order), and picks the combination with the fewest empty cells, then the least widening. Holes no feature can fill are ACCEPTED (three lone metrics in 4 columns, a lone pinned metric, two heroes plus one metric: 1 to 3 empty cells in the last row). Item order: Signature hour (feature) follows the hero in Time, so with the default pins Time is Signature hour (4 wide) + 3 metrics (1 empty cell). The result is written per tile as CSS custom properties through the CSSOM (`--span4`, `--rows4`, `--span2`) and consumed by the `@container` rules as `grid-column: span calc(2 + var(--span4,0))`. Recompute on render, pin / unpin and the preview data-state switch; expanding a tile never touches a span. The Pinned group uses the same function. Verified: the sketch and the canvas implement the same rule and agree in all 309,247 group/pin/column cases (node), no hero or metric is ever widened, and no result has more holes than leaving the group alone; DOM check: expanding any tile moves nothing.
- Tile anatomy: label (12 px caps, muted, with the group dot), value (32 px / 650; hero value up to 56 px), unit (14 px muted), rule line (12.5 px muted: what it counts), optional chart. Pin star top-right, 44 px target.
- Default pins: Logged in, Most-played tank, Most damage. Pinned tiles are full tiles at the top, in their original order; unpin returns them to their group. A pinned tile whose source is absent is left out of Pinned.

## Tiles (from the insight catalog, spike 003)
Time: logged-in days (union of session intervals over ALL account folders; "in battle" is a separate lifetime figure), longest streak, longest session, busiest day, signature hour. Tanks: most-played tank (name, class, tier, nation), favourite class, tanks played, favourite nation. Records: most damage / XP / kills in one battle, sniper series. Totals: credits earned ("880 million" or "0.88 billion", never a raw 0.88), battles + win rate, orders (count only).
Rules the numbers must follow:
- Never sum lifetime stats across two exports of the same player. Never show a mode mix from the battle-types table (it covers about 6 % of battles). Battle-type codes stay unlabeled.
- Tank names/class/tier come from a build-time table (spike 001: official WG API, key in `.env.local`, about 19 KB gzip, keyed by tag AND numeric tank_id, fallback name and "class unknown" for retired tanks). Records name their tank through the numeric id. Read the Wargaming Terms of Use before committing the table.
- Hall of Fame = records from the MAX/series columns; the ACHIEVEMENTS (medals) column is empty in real exports.
- Sensitive by default: orders = count only, chat = count only, no clan names, bans or money amounts on the Overview.
- Small-sample guard: no "best win rate / average" from under 100 battles per tank. Never estimate WN8 / marks / mastery.
- Wall-clock times, no timezone, same as Playtime.

## Behaviour (all measured in sketch 030)
- **Expand down in its column.** Click a tile: it grows downward and does not move sideways or change width (clicked tile x/y/width delta 0, scroll 0). While a tile is open its siblings keep their natural height (`.bento:has(.tile.open){align-items:start}`); only content below moves, animated.
- **No jump.** Tiles are never re-rendered after the first paint (they are toggled or moved). Changes go through the View Transitions API with CSSOM-set `view-transition-name`s when available and `prefers-reduced-motion` is off; scroll is adjusted so the changed tile stays under the pointer. State never depends on the animation: a 600 ms fallback applies the change if the transition callback does not run, the promises are caught (a newer transition may skip the older one), and the wanted state is recorded synchronously so two quick clicks mean open then close.
- **Keyboard (roving tabindex).** Exactly one tile button is tabbable (the last focused one; initially the first in DOM order), so Tab crosses the grid in one stop. ArrowLeft / ArrowRight: previous / next tile in DOM order across groups (Pinned first); ArrowUp / ArrowDown: the tile visually above / below (bounding rects: nearest tile whose horizontal extent overlaps, in the adjacent row; a hero below-neighbour is the one with the largest overlap, ties go left); Home / End: first / last tile; Enter / Space: expand (native button); Esc: close and return focus to the tile (also from the "Open <Section>" link); **P**: pin / unpin the focused tile and announce through the live region. The tile button carries `aria-keyshortcuts="p"` and the hint line reads "Arrow keys move between tiles, P pins the focused tile, Esc closes." The star stays a real `<button>` for pointer, touch and screen-reader browse mode, with `tabindex="-1"` because P makes pinning keyboard-reachable. When a pinned tile moves in the DOM, focus is restored to the element that had it (a moved node would otherwise lose focus). Verified by dispatching key events: one `tabindex=0`, correct targets at 4 / 2 / 1 columns, P keeps focus and announces "Pinned Longest streak, 4 pinned", Ctrl+P ignored. Note: browsers do not fire focus events in an unfocused document, so the roving stop is also set explicitly when keys move focus. The tile is ONE `<button aria-expanded>` whose content is only phrasing elements (spans with `display:block`; no `div`s, no `role="img"` inside a button). Charts are `aria-hidden` and each tile adds a visually hidden one-line summary ("Chart: logged hours per year, 14 years, peak 2015 with 1,180 hours.").
- The star is `<button aria-pressed>` with a FIXED label ("Pin <tile>"); a changing label plus `aria-pressed` reads as "Unpin X, pressed". Announce through a polite live region: "Pinned <tile>, 4 pinned" / "Unpinned <tile>, 3 pinned".
- **Absent data:** never a zero. Absent tiles are not drawn one by one; each group shows ONE dashed row, "Not in this export: <tile names> · needs <file names>" (users do not think in files, so say what is missing and what would supply it). Pinned tiles whose source is absent drop out of Pinned.
- Each tile carries its rule on the face and its longer definition + source on expand. Expanded content: "How it is computed", "Reads", and an underlined "Open <Section> →".
- **Phone two-up (OPTIONAL, undecided; default stays one column).** A preview-bar control "Phone layout: one column | two-up" turns on `data-phone="two"`. Only when the pane is 340-479 px wide, metric tiles sit two per row; hero and feature stay full width, row-spans reset; label text switches to the optional `short` field on metric items (`Top damage`, `Top XP`, `Top kills`, `Top nation`; others keep their label) by CSS only: both labels are in the DOM, the long one stays in the accessibility tree (visually hidden) and the short one is `aria-hidden`. Fill rule is the same `--span2` as the 2-column layout (an odd metric at the end of a row becomes full width). Tile padding drops to 12 px, metric values to 26 px (18 px for long text), rule line 12 px, definitions wrap anywhere. Star: label text width is 164 - 12 - 12 - 34 = 106 px at a 340 px pane; measured 0 overlaps between label and star glyph or star box, and 0 horizontal overflow, with every metric tile closed and open. **An open metric tile grows DOWNWARD inside its own half-width column** (x, y, width and scroll delta 0, siblings keep their x and width; measured on all 16 tiles). It reads fine: 132 px text column, definition about 5 lines, "Open Vehicles ->" intact, open height 301-376 px for half-width tiles; the cost is a tall blank cell beside it (the sibling keeps its natural height, about 240 px of dead space). Verdict: acceptable as an optional density mode because it keeps the "never moves sideways" rule; spanning both columns when open would read better but would move the tile sideways and change its width, so it is rejected. Caveat: in the sketch shell a real 360-400 px phone yields a 294-334 px pane (frame padding 16 + pane padding 16 + borders), below the 340 px gate, so two-up only shows from a ~406 px viewport; the real app has less chrome, but decide the gate against its real pane width.
- Rejected: side inspector panel, popovers and bottom-sheet explanations (028), full-width expansion, flip-in-place and a reserved explain bar (029 alternatives), and the other alternatives in 023-027 (prose, then-vs-now, small multiples, typical week, top-5s, ask-your-data, timeline, sticky chapters, player dossier), kept only as ideas.

## Colour and elevation (user decision 2026-10-22)
- **Colour is limited to two things**: a small **group dot** beside the group heading and each tile label (Time `#1f7a74`, Tanks `#c26a1b`, Records `#8f4a80`, Money `#3a6aa8`; neutral `#8c8c8c` on absent tiles) and an **amber star on pinned tiles** (fill `#e0a020`, stroke `#a8710a`; unpinned stroke `#8c8c8c`; the pinned section dot is `#e0a020`). Tiles stay white and numbers stay ink `#111`; tinted tiles and coloured numbers were tried and dropped as too much. **Value charts are the exception:** years, hour-of-day, top-5 bars and the class split are coloured by value on a Grafana-style scale (`chartColor` tweak: heat | teal).
- **Value scale (chart colour):** light green `#4fb27f` -> olive `#6b8a14` -> dark gold `#8c6400`, eased (`t^1.5`) so most bars stay green and only the highest turn gold. **Lightness falls as the value rises**, so the peak stays the darkest bar in greyscale and for colour-blind users (an earlier equal-lightness green-to-yellow version failed this). Contrast against white 2.6 : 1 / 4.0 : 1 / 5.3 : 1; graphics may sit below 3 : 1 under WCAG 1.4.11 because the peak is named in text and bar length carries the value. Grafana's bright yellow `#f2cc0c` is 1.5 : 1 and would make the peak the faintest bar. A low-to-peak legend (48 px gradient) sits in the heading of every group that contains a chart. The peak bar is labelled in text right above it (`1,180 h · 2015`, `20:00`), chart baseline 1 px, axis text 12 px.
- **Shadows (lifted):** rest `0 1px 2px rgba(17,17,17,.05)`; hover (only under `@media (hover:hover)`) `0 4px 12px rgba(17,17,17,.08)` with the border unchanged; open tile `0 8px 24px rgba(17,17,17,.10)` plus an ink edge. Hairline `1px #dcdcdc` borders are kept in every mode (shadows vanish in forced-colors mode; the border is the fallback). Phone: soft rest shadow only. Not on: list pane, pinned strip, dashed absent tiles.
- The open tile's 2 px ink edge is `border: 1px ink` + `outline: 1px solid ink; outline-offset: -2px`, so it never changes layout and leaves `box-shadow` free for elevation.
- The canvas has tweaks to compare: `accents` (dots on/off), `density`, `elevation` (none | soft | lifted).

## Build notes (verify when planning)
- **CSP / no inline styles in the build:** the app ships `style-src 'self'` (no `unsafe-inline`) and `svelte/no-inline-styles` is an error. The sketches use inline `style=""` in a few places and are not copy-paste: use classes for dots, stars and shadows; write dynamic positions or `view-transition-name` through the CSSOM (`el.style.x = ...`), as `ChartTooltip.svelte` does for left/top.
- One pure module builds the insight list from already-loaded aggregates (unit-testable in node like `overview-model.ts`; no worker query from the Overview, as today); one tile component; one grid. No new runtime dependency.
- Sessions-derived figures (streak, busiest day, longest session, signature hour) probably need new aggregates beside what Playtime reads. Check that the record columns (`DAMAGE_MAX`, `XP_MAX`, `FRAGS_MAX`, `*_SERIES_MAX`, `MAX_*_VEHICLE`) are in the ingest allowlist; `MAX_*_VEHICLE` are numeric tank ids.
- Pins persist on the device (localStorage, guarded with try/catch; the page must work without it).
- Contrast: unpinned star `#8c8c8c` is a 3.4:1 UI mark on white, `#8c8c8c` is never text; re-run `tests/unit/charts/contrast.test.ts` after adding the dot and star colours.
- Announce pin / unpin through the existing live region (see `tooltip-pin.ts`: no data in the spoken strings).
- Also in the build: tabular numerals on the whole page (`font-variant-numeric: tabular-nums`); text values longer than 9 characters on a metric tile drop to 22 px with `overflow-wrap: anywhere` ("Czechoslovakia"); the "Open <Section> →" link keeps a 44 px target; one-line hint under the game switcher ("Click a tile to see how it is computed. Star a tile to pin it to the top."); `@media (forced-colors: active)` rules so bars, dots and the legend survive (system colours, 1 px outline); date and number formatting should use `Intl` with the browser locale in the build (sketches hard-code `en`).
- Wording: "logged in" is counted in 24-hour days and the rule line says so; "one login to logout" (not "without a break", idle time can inflate it); keep "in battle" and "logged in" apart.
- Known open items from the design review (not applied yet): a game-switcher style that is lighter than the hero, a chevron cue that tiles expand, forced-colors polish, dark-mode readiness (move dot, star and scale colours into CSS custom properties). The design canvas (`sources/design-canvas-overview/`) still breaks on the viewport; give it the 880 / 480 pane thresholds when it is next edited. Decide whether the phone two-up variant ships.
- Fixed in the sketch while doing this: the class-split bar rendered empty because `.blk` (display:block) beat `.stack` (flex); `.stack.blk{display:flex}` restores it (check the same cascade in the real component).
- In the build, put the pure `fillSpans` beside `overview-model.ts` (same unit-test style: the node simulation of dense placement is the oracle; enumerate the pin subsets) and set the spans as CSSOM custom properties, never `style=""` attributes (CSP).
